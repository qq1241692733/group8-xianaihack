## 一、先说「无用」

手机里存着很多这样的东西：

- 一段十几秒的录音，不知道当时为什么录；
- 一张照片，拍的是一棵树、一个楼道、一只猫，说不清它有什么意义；
- 一句话，写在备忘录角落里 ——「今天风很大」「终于没人找我了」。

它们不构成任何成果，不指向任何目标，甚至**过一段时间，连你自己都想不起来为什么会留下**。

这就是「此刻」说的无用：

> **无用 = 记录当时，你不知道它有什么用。**

它不要求这些碎片后来变得有用，也**不要求它们完整** —— 可以只是一段声音，或只是一句话，
或只是一张照片。**记录一个场景，不是完成一张表。**

但「无用」不是「没有价值」：

> **无用之用 —— 不是没有价值，而是价值要在关系里才显现。**
> 一张照片没什么；当它和那段风声、那句话、三个月后的另一张照片放在一起时，
> 原本的意义和感受才回来。

## 二、为什么做它：整理旧文件时，线索自己浮了出来

这个 App 的起点不是「我发现了一个痛点」，而是一次很普通的整理。

我把过去攒下的照片、录音和备忘重新翻了一遍。本来只是想归置一下文件，
结果翻着翻着，一些东西自己浮了出来：

- 不同日期拍的那棵树下，好几张照片里都有一只白猫 —— 我拍的时候根本没看见它；
- 一段风声，和那句「这道纹路，像老家院子里的那棵树」，是同一个下午留下的；
- 某一个时刻，在后来其实重复出现过很多次，只是每次都散在不同的地方。

**这些关系一直都在，只是散落着，没有人把它们摆到一起。**
一旦摆到一起，意义和感受就自己回来了 —— 而我什么都没有添加，只是重新看了一遍。

于是我想：如果**记录的时候就是按「场景」记的**，而不是按「文件类型」存的
（照片进相册、录音进录音机、文字进备忘录），
那后来的这一次整理，就不用再从头重来一遍。

> **这就是「记录此刻」的由来 —— 它不是为了解决什么问题，只是想换一种记录方式。**

## 三、换一种记录方式，能得到什么

### 1. 一个场景，是一条记录，不是三个文件

照片、声音、文字三个**真实**入口（真麦克风 `MediaRecorder`、真相机 `getUserMedia`）
收在首页底部同一簇里，拇指半径内完成。可以一次攒下好几个，再**长按「记下此刻」一起落下** ——
它们从此共享同一个 `momentId`，是**一件事**。

| 媒介 | 留下的是 |
| --- | --- |
| 📷 照片 | 我看见了什么 |
| 🎙 声音 | 现场是什么感觉 |
| ✍️ 文字 | 只有我自己知道的那一句 |

> 照片留下看见的，声音留下现场，文字留下只有自己知道的事。**它们合起来，才是那个场景。**

而且**不必凑齐** —— 只有一张照片、只有一句话、只有一段声音，都成立。

### 2. 留下的是感受，不是文件

回看那条旧记录时，照片出现，**风声真的响起来**，那句关于老家的话还在下面。

> 这不是翻到一张照片，是重新接近当时的自己。

### 3. 线索会把散落的碎片串起来

AI 从你自己留下的材料里找线索 —— 可以是一个词、一样东西、一句你说过的话。
它**不看时间**，所以跨月、跨年的碎片也能被拢到同一条线上。

于是有了那种「意外发现」：不同日期的树下记录被放在一起，几张原图里都出现了那只白猫，
你才注意到自己随手留下的画面里，还有一条从没留意过的线索。

也可以**主动开口**。比如对着「理解」说一句：
**「把以前记下的那些第一次，也帮我找出来。」**
旧照片、标注过的旧录音被找回，确认后放进一个合集，那段第一次讲话的录音响起。

> 我负责留下当时在意的东西，AI 帮我看见它们之间的联系。

### 4. 它只呈现，不解释

AI 不写、不编、不加东西。**呈现出来的每一样东西，都必须来自你自己留下的材料。**
它不说「你最近压力比较大」，它只把你 9 月 3 日的一段洗衣机声、9 月 11 日那句
「终于没人找我了」、昨天那段 31 秒的窗外摆在一起，然后说一句：

> **「这三次，你都在所有人安静以后才留下东西。」**

不给结论、不打分、不贴标签、不催行动。展开顺序是一条铁律：**先材料，后结论。**

> 一旦它开始替你编意义，「只是呈现」就崩了 —— 用户会立刻感到被冒犯。

## 四、这些不是文案：五条硬约束

上面说的每一条，都能在代码里找到对应的一行兜底。

### 约束一：不要求有用，也不要求完整

采完**不给奖励**：没有 ✦、没有「已保存」的成就感设计、没有撒花，
东西只是悄悄攒到球边，落下时球变密一点。你做了唯一能做的事，而它不产生结果。

### 约束二：一个场景是一条记录

三种媒介攒在一起共享 `momentId`，一次长按一起落下，在类型上就是一次事务：

```ts
// app/src/features/memory/types.ts
export interface Entry {
  id: string; kind: EntryKind; createdAt: number
  text?: string; durationMs?: number; blobRef?: string
  tags: EntryTags; tagSource: TagSource; meta?: EntryMeta
  momentId?: string   // 同一次「此刻」的组号
}
```

### 约束三：AI 只呈现，不解释

- 观察一律表达为「我注意到……」，而非「你就是……」；
- 不输出心理疾病、人格判断；
- 不添加任何它没在你材料里看见的东西。

### 约束四：首页不给数字

打开 App 第一眼不是功能，而是**一颗用网点画出来的球**。留下的越多，网眼越密 ——
**密度就是那个数字，只是它不可被计算。**

不给数字的理由很朴素：**只要屏幕上出现「你已经留下 37 条」，
注意力就从「那一刻」被挪到了「这个数」上。**
它不是一个统计，也不是一个进度，它只是一个正在变密的东西。

这一条靠**类型系统**强制，不靠自觉遵守 —— `Entry` 上根本不存在能算出
「专注时长 / 完成率 / 连续天数」的字段，`db.ts` 里也没有对应的表，
`repo.test.ts` 会断言 `Entry` 的键不含那 9 个效率词。

> 类型系统里表达不出来的东西，界面上也就做不出来。

### 约束五：「什么也不留」也是完整的答案

它收在右上角一个安静的角，不跟三个采集入口抢层级。
点下去是一次虚线圆旋入的全屏浮层，停一会儿自己收起 —— **不写任何数据**。

> 不留也是一次留，但留的不是数据。

### 明确不做的

排行榜 · 连续打卡 · 复杂任务管理 · 完整健康数据 · 复杂社交 · 复杂商业化 ·
过度复杂的 Agent 多工具调用。

## 五、四个页面

| 页面 | 回答什么 | 谁来组织 | 入口文件 |
| --- | --- | --- | --- |
| **此刻**（首页） | 现在有什么想留下？ | 用户 | `src/screens/MomentScreen.tsx` + `features/timefield/` |
| **时间** | 最近发生了什么？ | 规则（时间轴，触感而非数字） | `src/screens/TimeScreen.tsx` |
| **发现** | 这些碎片之间有什么联系？ | AI 按线索整理给你看 | `src/screens/DiscoverScreen.tsx` + `data/discoveries.ts` |
| **理解** | 我想找回某件事 | 说出大概，它把相关记录翻出来 | `src/screens/UnderstandScreen.tsx` |

- **发现**是「册架 → 卷内」：AI 把相关记录收成一册一册的档案（**档案 = 集合，不是格式**）；
  另有**守望** —— 你可以说「帮我留意孩子」「留意想不到的声音」，它会一直替你留意，
  跨时间地把碎片拢过来。
- **理解**的检索走**精确日期 + 聚合 + 文本兜底**三路：
  「你还记得 8 月 17 日吗」靠日期，「你已经提到它 7 次了」靠跨条目聚合 ——
  都不是语义相似能办到的事。

## 八、技术要点

**技术栈**：Vite 8 · React 19 · TypeScript 5.9 · Zustand · Dexie(IndexedDB) · Zod · Vitest · Capacitor（安卓打包）。

**本地优先**：原始媒体与记忆层都在设备内，LLM 只是可选的增强层。

- **记忆层** —— `Entry` 写入时打一次标签（规则 / 元数据 / LLM 三层管道）；
  之后所有计数都是**读的那一瞬间**的纯函数，`Entry` 上永远不多一个字段。
  标签维度刻意**不建索引**：个人几千条封顶，内存过滤是微秒级，建 `multiEntry` 索引只会让写入路径变复杂。
- **成册靠线索，不靠时间邻近** —— 跨月跨年的「第一次」永远不在同一个时间窗口里，
  所以聚合走的是 `clues` / 守望的**子串命中**（scene / text / themes / people / places），
  **不看时间**。这正是「一棵树下不同日期的照片」能被拢到一起的原因。
- **检索不做向量 RAG** —— 文档里最精彩的两个场景恰好是向量检索的盲区：
  按**精确日期**召回（语义搜「焦虑」永远命不中「今天风很大」），以及跨条目 **COUNT** 聚合（这是聚合查询，不是 top-k 相似）。
  > 护城河在**写入时的标签提取**，不在检索算法。
- **那颗球** —— 唯一绘制源 `features/timefield/dotOrb.ts`（Canvas 侧另有一套 `TOKENS`，
  因为 CSS 变量画不进 canvas；切主题要 `orb.build()` 重建，颜色是烘进离屏纹理的）。
- **昼夜双主题** —— `html[data-theme='day']` 令牌层 + `ThemeSwitch.tsx`，三态 system / day / night，首帧防闪。
- **照片的真实信号** —— EXIF 保留真实拍摄时间 / 坐标；「让 AI 看一眼画面」是默认关闭的可选增强层，打开后缩到 512px、剥掉 EXIF / GPS 再发出去。

## 九、隐私与项目结构

### 隐私

- **原音原图默认不出设备**：只有**文本与标签**会离开设备，原始音频 / 图片存在应用私有目录（IndexedDB 的 `blobs` 表）。
- **API Key 永不出服务端**：LLM 调用经开发期代理转发，Key 只存在 `.env.local`，绝不进客户端产物。
- **能本地做的分析优先本地做**：写入时的标签提取默认走本地规则词典 + 元数据，不联网。
- **AI 不贴标签**：不输出心理疾病、人格判断；观察一律「我注意到……」，而非「你就是……」。
- **可随时删除**单条记录或全部时间档案。

### 项目结构

```
the_time/
├─ app/                正式前端工程（Vite + React + TS）—— 产品本体
│  ├─ src/screens/     四个页面

│  ├─ src/data/        种子数据 · 发现档案 · 合集 · 守望
│  └─ android/         Capacitor 安卓工程
```
