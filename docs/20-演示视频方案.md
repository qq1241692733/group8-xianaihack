### P1 录制环境：两个技术坑先说清

- `getUserMedia`（麦克风 / 相机）要求安全上下文。桌面 `localhost` 天然满足；**手机连局域网 IP 会被浏览器直接拒绝**，必须用 `npm run dev:host`（会自动挂自签证书，手机会弹一次拦截）。
- 两个可选拍法：**真机录屏**（能看到真实的授权弹窗，最硬）／**桌面浏览器 + 手机模型**（画质最稳、可重复，但授权弹窗的"真实感"弱一点）。
- 无论哪种，录制前都跑一次质量门：`tsc` / `eslint` / `vitest`（88 例），确认没有半截状态被录进去。
- 还要先想好一个细节：真机上**「不留」那一步是要真点的**，如果误触了「听见」，那一遍就得整段重录。

### P1 可验证入口：一个容易漏的技术点

`app/` 是 Vite 工程 + 一个 `server/llmProxy.ts` 中间件，**Key 只活在中间件里，不进客户端产物**（这条隐私边界是产品的卖点之一）。但这也意味着：**纯静态托管会把 `/api/llm` 代理丢掉**，公网版里走模型的那条路会回落到一句兜底话。

两个处理办法，二选一：部署时带一个边缘函数做同样的代理；或者视频里如实说清「自由输入那一路是本地联网能力，公网 Demo 走的是确定性路径」。**不处理也不说，是最差的选项** —— 评委一试链接就发现输入框不返回，反而扣「真实」。

3. **一屏最多一颗彩色球 + 一处金。** 加字幕、贴图、进度条时不要引入第三种强调色；金只留给「你按下的那一下」这个动作回执，不做装饰。
