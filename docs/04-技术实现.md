## 一、把「无用」写进 schema —— 用类型系统强制产品哲学

**问题**：产品要求首页那些效率数字「算不出来」。靠文案约束不可靠，
靠开发者自觉更不可靠——总有人会「顺手」加一个 `streak` 字段。

**方案**：让这件事在**类型和数据库层就做不到**，并用测试守住。

```ts
// app/src/features/memory/types.ts
export interface Entry {
  id: string
  kind: EntryKind          // 'sound' | 'photo' | 'word'
  createdAt: number
  text?: string
  durationMs?: number
  blobRef?: string         // 原始媒体在 blobs 表的 key，Entry 保持轻量
  tags: EntryTags          // 写入那一刻提取一次，不可回退的加工
  tagSource: TagSource     // 'llm' | 'rule' | 'seed'
}
```

数据库连表都不给它——3 分钟专注不落库，所以它没有资格拥有表：

```ts
// app/src/features/memory/db.ts
this.version(1).stores({
  entries: 'id, createdAt, kind, [kind+createdAt]',
  blobs: 'id',
  meta: 'key',
})
// 表结构里没有 focusSessions、没有 stats、没有 streaks。
```

这条线在四处同时被钉住，任何一处想加回来都会红：

```ts
// app/src/features/memory/repo.test.ts
const forbidden = ['streak','completionRate','dailyGoal','done',
                   'completed','status','score','progress','count']
expect(Object.keys(entry).filter((key) => forbidden.includes(key))).toEqual([])
```

```ts
// app/src/features/memory/extract.ts —— 连标签词典也不许出现评价性词
/**
 * 词典刻意不含任何评价性 / 成就性词（完成、坚持、进步、加油…）。
 * 类型系统里表达不出来的「有用」，界面上也就做不出来——这条同样适用于标签。
 */
```

计数只活在读的那一瞬间，不落回条目：

```ts
// app/src/features/memory/aggregate.ts
/** 全部是纯函数：入参不动，返回值是原始值或新数组，Entry 上永远不多一个字段。 */
export function countByTag(entries: readonly Entry[], dim: TagDim, value: string): number {
  return entries.filter((entry) => entry.tags[dim].includes(value)).length
}
```

> 类型系统里表达不出来的「有用」，界面上也就做不出来。

## 二、那颗球：材质写成纯函数

**问题**：我把「视觉进不了测试」当作这个项目最大的口子。**它现在仍然是个口子** ——
画布的像素没有进 vitest（jsdom 里没有 2D 上下文）。
能测的是**从数据推出来的那部分**：密度级是纯函数（`evidence.ts`，有单测）；
绘制本身只能靠真机截图对拍。

**方案**：球是**一层网点**画出来的，而铺网这件事被抽成一个纯函数：

```ts
// app/src/features/timefield/dotOrb.ts
/**
 * 把网点铺进当前路径的坐标空间。调用方负责裁剪（圆）与缩放。
 * 抽出它是因为**三处必须同源** —— 首页那颗动态的、理解页 34px 那枚、
 * 拍照快门那面 70px 的，用的是同一个函数。各画一遍，等于以后改球的颜色一定会漏一处。
 */
export function drawDotOrbTexture(ctx, size, gap, light, dark): void
```

三处只有三个参数不同（`size / gap`），几何一个字不改：隔行错半格、左上受光
（`0.30 / 0.24`，全 App 只有这一个光源方向）、边缘两套衰减（一套收半径、一套淡出，
球因此有「边」）。

**纹理必须是确定性的**：伪随机用 `mulberry32(20260926)`，同一颗球每次画出来一模一样。
会抖的纹理不是材质，是噪音。

### 2.1 密度就是那个数字

球随记录变密 —— 这是全 App **唯一一处「数量影响界面」**的地方，而它影响的只是密度。
屏幕上不出现那个数字：密度就是它，只是不用写的。

```ts
export function levelOf(entries: readonly Entry[]): number {
  return Math.min(9, Math.floor(Math.sqrt(entries.length) * 1.7))
}
// 首页实际用的是：levelOf(entries) + min(3, 攒着还没落下的件数)
```

开方是为了压住前期：第一条带来的变化最明显，第 20 条几乎看不出来（13 条种子落在第 6 级）。
每密一级，直径 `+2.1`、网点间距 `-0.052`，暗部再往深处走一档。

**攒着的东西也让球密一点**（临时最多 +3 级）：球是「你已经留下多少」这一件事的读数，
攒着的是一个**承诺**，还没兑现 —— 所以它只加一点点、落下前不改变事实。

### 2.2 昼夜的读法相反

同一个动作，两种底色上的读法完全不同 —— 所以球的两端值与「变密往哪走」必须分主题：

| | 昼版（纸白底） | 夜版（墨蓝黑底） |
| --- | --- | --- |
| 球是什么 | **墨点** —— 底透出来，网眼越密看着越沉 | **光源** —— 网眼越密看着越亮 |
| 留下得越多 | 更沉 | 更亮 |
| 暗部去向 | 往**暗**走 | 往**亮**走 |

画布拿不到 CSS 变量的实时值，所以色板由 `cssVar('--c1')` / `cssVar('--c2')` 读进来 ——
`tokens.css` 仍是颜色的唯一出处；只有画布专有的量（辉光、高光强度、外圈、按下光晕）
留在 `dotOrb.ts` 的 `ORB_THEME` 表里，按 `useTheme().mode` 取。

## 三、攒元素与长按：三条独立的判定路

首页的动作不再是「按住展开四个方向」，而是**攒**：点文字 / 图片 / 声音各往球上攒一个
元素，长按「记下此刻」才一次落下。两处细节值得写下来。

### 3.1 卫星卡与球心同源

攒下的元素绕球浮在三个方向上（文字在上、图片在左、声音在右）。坐标必须和球心同源，
否则球一变密变大，卡就漂了：

```
.sats 铺满 .orbwrap（卡层与球的画布同一个坐标系）
每张卡：left:50% / top:50% 为原点，再按方向平移 px —— 平移量现算，写进 --rest
同一方向多张时，沿**垂直方向**以 0 为中心错开（FAN）
```

一处**必须分开**的东西：*计数*与*槽位*。第一版复用了同一个对象，结果一张卡让徽章显示
「2」。计数是「这一向有几张」，槽位是「我正在渲染第几张」——两个量，两个对象。

### 3.2 长按判定：三条路缺一不可

```ts
// app/src/features/timefield/holdController.ts
// ① rAF 把进度画出来，跑到 1 → 提交
// ② setTimeout(holdMs) 兜底 → 提交（rAF 被冻结时它还在跑）
// ③ 松手那一刻用**墙钟**（now() - startAt >= holdMs）再判一次 → 提交
```

**为什么不是一句 `setTimeout` 就够**：切走的标签页 / 无头环境会**同时**节流 rAF 与 timer。
只留 rAF，后台标签页永远交不了；只留 timer，节流后同样跑不到头；只有墙钟还说得出
「其实按够了」。三条路走同一个收尾，`holding` 一落就幂等，重复触发不会有第二次。

时钟 / rAF / 定时器全部可注入，所以这三条路都能用假时钟钉住（见 `holdController.test.ts`）。

> **踩过的坑**：判断手指「移出按钮」**不要用 `pointerleave`** —— 按下之后浏览器偶尔会补
> 一个**不带坐标**的假 `leave`（clientX/Y 全是 0），照单全收会把长按误取消。
> 要用 `pointermove` 看真实坐标。这个坑在 demo 阶段做 CDP 事件探针时抓到的。

### 3.3 入口与胶囊都是真 button

三个采集入口、长按胶囊、右上角「什么也不留」都是**真正的 `<button>`**：键盘可达、
`:focus-visible` 焦点环。长按胶囊上 `Enter` / `空格` **按住**即开始计时、松开即判定
（键盘也有「按住」这个概念），`Esc` 取消。无攒入内容时胶囊 `disabled` —— 不可用的东西
不该能被 Tab 走进去。

## 四、弹簧：不感知时间步长的插值一定会抖

**问题**：线性插值 `cur += (target - cur) * 0.07` 不感知时间步长，掉帧时快慢不一致。

**方案**：按下、方向偏移、进食脉冲全部由**真正的阻尼弹簧**驱动，每帧按 `dt` 积分：

```ts
// app/src/features/timefield/dotOrb.ts
this.press += (this.pressT - this.press) * Math.min(1, dt * 11)
this.dirAmt += (this.dirT - this.dirAmt) * Math.min(1, dt * 9)
// 进食：ẍ = -k·x - c·ẋ
this.feedV += (-this.feed * 58 - this.feedV * 8.2) * dt
this.feed += this.feedV * dt
```

按下与方向是**指数逼近**（无过冲，响应约 0.1s）；
进食那条是**真弹簧**，`k=58 / c=8.2` → `ζ = c / (2√k) ≈ 0.54`。
0.54 是欠阻尼，理论上有一点回弹，但它作用在 `0.062` 的幅度上 ——
残余过冲不到一个像素，读不出来。

> **降级**：`prefers-reduced-motion` 或截图模式（`&cap=1`）下，这三条弹簧直接落到终态 ——
> 虚拟时间推不动 JS 弹簧，不落终态就会截到上一帧的值。

## 五、发现：存判据，不存死数据

**问题**：截图里那行「2026.09.10 — 09.26」看起来是文案，其实应该是**从记录里数出来的**。
一旦写成字面量，改一条种子就会让卡片开始撒谎——而演示时最不能接受的失败，
就是点开一张发现卡却被告知「内容不存在」。

**方案**：每条「连接」只存一个**判据**，卡片内容在渲染时从真实记录现算。

```ts
// app/src/data/discoveries.ts
export const DISCOVERY_DEFS: DiscoveryDef[] = [
  { id: 'd-project', axis: 'theme', title: '又在想那个项目',
    match: (e) => e.tags.themes.includes('项目') },
  { id: 'd-window',  axis: 'theme', title: '总是看向窗外',
    match: (e) => e.tags.places.includes('家') || e.tags.scene.includes('窗外') },
  { id: 'd-late',    axis: 'time',  title: '很晚留下的片刻',
    match: (e) => { const h = new Date(e.createdAt).getHours(); return h >= 23 || h < 4 } },
]
```

`from` / `to` 从命中的记录里遍历得出，不写文案；条数不足两条不成卡——
**一条不叫「联系」**。

两种轴不是巧合，是「不写情绪标签，写生活证据」的两条落地路径：主题型按 `tags` 命中，
时间型按「一天里的位置」命中——23:47 和 23:52 不需要任何形容词，你一看就懂。

配套的对账测试锁三件事：**引用 id 真实存在、跨度等于真实起止、时间型卡每条都真在深夜**。

## 六、本地优先的记忆层与索引策略

**问题**：记忆检索要支持「按精确日期召回」（场景 C）和「跨条目计数」（场景 D）。
一个自然的冲动是上向量库 / 给所有标签建索引。

**方案**：两个决定——**写入时提取标签**（护城河），**检索时只用极简索引**。

写入时用本地规则词典提取，同步、离线、可重复：

```ts
// app/src/features/memory/extract.ts
/** 永不抛错：匹配不到就是空标签，不是失败。 */
export function extractTags(draft: EntryDraft): EntryTags {
  const haystack = [draft.text ?? '', draft.sceneHint ?? ''].join(' ')
  const tags = createEmptyTags()
  tags.themes = collect(haystack, THEME_RULES)
  tags.emotions = collect(haystack, EMOTION_RULES)
  tags.places = collect(haystack, PLACE_RULES)
  tags.people = collect(haystack, PEOPLE_RULES)
  tags.scene = draft.sceneHint?.trim() || tags.places[0] || ''
  return tags
}
```

索引只建在结构维度上：

```ts
// app/src/features/memory/db.ts
/**
 * 只索引 id / createdAt / kind / [kind+createdAt]。
 * 标签维度（themes / emotions / people / places）刻意不建索引——个人几千条封顶，
 * 内存过滤是微秒级；而为嵌套数组建 multiEntry 索引会让写入路径变复杂，
 * 还容易在标签更新时留下不一致的索引。复杂度花在"写入时提取标签"上更值。
 */
```

路二（聚合）与精确日期检索：

```ts
// app/src/features/memory/aggregate.ts
/** 精确日期检索：容差内离目标最近的那条。
 *  平手时优先「word 且有 text」——8/17 那张卡片要的是那句话，不是一条没有文字的声音。 */
export function entryNearestDate(entries, targetTs, toleranceMs): Entry | undefined
```

喂给 LLM 的也不是整库，而是一份最小摘要：

```ts
/** 只给计数与最近几条 caption——不把整库倒给模型。 */
export function memoryDigest(entries: readonly Entry[], recentCount = 5): Digest
```

**为什么不做向量 RAG**：护城河在写入时的标签提取，不在检索算法。两个最精彩的场景
恰好是向量检索的盲区（精确日期、COUNT 聚合），详见
[01 · 产品亮点](01-产品亮点.md#亮点六记忆检索不做向量-rag)。

## 七、真实录音与拍照：异步生命周期 + 降级是设计的一部分

**问题一**：`MediaRecorder` + `getUserMedia` 是异步的，而 React 开发模式（`StrictMode`）
会把 effect 跑两遍。没有保护的话，**第一遍拿到的音频流会在第二遍生效后继续偷偷录下去**。

**方案**：用 session 计数器给每一路取流打标记，过期的一路立即停掉；取消路径把 `onstop`
置空，确保**丢掉的录音不产生任何产物**——既符合「没用的事不留痕」，也避免内存泄漏。

```ts
// app/src/features/capture/useRecorder.ts
const session = ++sessionRef.current
const stream = await navigator.mediaDevices.getUserMedia({ audio: true })
if (session !== sessionRef.current) {          // 这一路已经被取消了
  stream.getTracks().forEach((track) => track.stop())
  return
}
```

**问题二**：`getUserMedia` 需要安全上下文。http 局域网、被拒权限、没有摄像头都可能发生。
演示现场不能因为一个权限弹窗就黑屏。

**方案**：把「拿不到相机」当作一种正常状态，用 Canvas 画一片「窗外」顶上。

```ts
// app/src/features/capture/useCamera.ts
export type CameraState = 'idle' | 'live' | 'denied' | 'unavailable'
// 「有没有 getUserMedia」在渲染期就能判定，所以不放进 effect 里再 setState 一遍
const supported = typeof navigator !== 'undefined' && Boolean(navigator.mediaDevices?.getUserMedia)
// ...
} catch {
  if (!cancelled) setState('denied')      // 如实降级，不假装成功
}
```

> 降级是设计的一部分，不是兜底补丁。

## 八、LLM 接入的形状与「回落兜底是一等公民」

**问题**：黑客松最怕演示时 AI 没找到；同时 API Key 绝不能进客户端。

**方案**：**Key 留在服务端**、**客户端只认形状**、**没有 Key 就回落兜底**。

```ts
// server/llmProxy.ts
if (!process.env.LLM_API_KEY) {
  res.statusCode = 200
  res.end(JSON.stringify({ ok: false, reason: 'no-key' }))   // 如实告知，而不是报错
  return
}
```

客户端只依赖一个**判别联合**的结果类型，不关心后端是模型还是兜底：

```ts
// app/src/features/agent/client.ts
export type LlmResult =
  | { ok: true; text: string }
  | { ok: false; reason: 'no-key' | 'not-implemented' | 'network' | 'bad-response' }
```

`reason` 是判别联合而非布尔——调用方能区分「没配 Key」和「网络坏了」。
而现在，两者都回落到 `FALLBACK_LISTEN`，**演示不会失败**。

**AI 说话的规矩也写进了代码**，不是靠 prompt 里的一句请求：

```ts
// app/src/features/agent/prompt.ts
export const VOICE_RULES = `你在「此刻」里说话。这个产品记录一个人的时刻，但从不评价他。
...`
export function sanitizeReply(text: string): string
```

**播放用队列，不用即时渲染**：

```ts
// app/src/features/agent/useAiQueue.ts
export function useAiQueue(): void   // 按 head.gapMs 逐条推进 store.aiQueue
```

队列留在 store 里 → 切 Tab 不丢、可以续播；每条消息自带 `gapMs`，
节奏是数据的属性，而不是散落的 `setTimeout`。

## 九、P0 叙事时序修正：从第一天就按正确语义长状态机

**问题**：原单文件版 `index_demo.html` 在脚本末尾无条件执行 `aiStart()`，AI 全部对话
（含分支选项、最终行动按钮）在进入 App 后约 10 秒内就流完。现场演示点「理解」时
直接看到结尾，第五/六/七幕的转折全没了。

**方案**：把「进入 App」与「进入理解」在状态机层就分开。

```ts
// app/src/features/agent/useAiQueue.ts
/**
 * 「理解」的消息只在**真有回执**时才出现 —— 没有「AI 开场」。
 * 原单文件版是进 App 就无条件跑完整场对话，现场演示点进「理解」只剩结尾。这是 P0 修正。
 */
export function useAiQueue(): void {
  const head = useStore((s) => s.aiQueue[0])
  const advance = useStore((s) => s.aiAdvance)
  useEffect(() => {
    if (!head) return
    const timer = window.setTimeout(advance, head.gapMs)
    return () => window.clearTimeout(timer)
  }, [head, advance])
}
```

**同批修正的参考稿问题**：

| 问题 | 修正 |
| --- | --- |
| AI 对话提前跑完（P0） | 队列留在 store、由 `useAiQueue` 在理解页挂载时逐条排空；没有开场戏 |
| 一句话输入 XSS / 破版 | 全程走 React 文本节点，不用 `innerHTML`；有测试守住尖括号原样保留 |
| 种子文案错字「地铁里有人在下雨。」 | 改为「外面在下雨。」 |
| 录音计时超 59 秒显示 `00:60` | `formatElapsed` 真进位，测试覆盖 `62:03` |

## 十、正确性细节

**时间格式**：只回答「这段声音多长」，不回答「你专注了多久」。

```ts
// app/src/lib/time.ts
/**
 * 录音计时：00:07 一路走到 01:23。
 * 原单文件版是 "00:" + pad(秒)，超过 59 秒会显示 00:60 / 00:61 —— 这里是真进位。
 */
export function formatElapsed(ms: number): string
```

**确定性伪随机**：球的网点纹理与碎片的散布都**不引入真随机** ——
用 `mulberry32(20260926)` 这类由固定种子驱动的伪随机，每次渲染都是同一张图。
不因重渲染而抖动，也不违反 React 纯函数约定（渲染期不取 `Date.now` / `Math.random`）。

```ts
// app/src/features/timefield/dotOrb.ts
/** 确定性伪随机。同一颗球每次画出来必须一模一样 —— 会抖的纹理不是材质，是噪音。 */
function mulberry32(seed: number): () => number { /* … */ }
```

**降级：把动效关掉，而不是把画面关掉。** `prefers-reduced-motion` 下呼吸停止、
涟漪与碎片收敛、弹簧直接落到终态、卫星卡不做入场回弹直接落位 ——
画面本身不缺任何信息（卡在哪、攒了几件，都还在）。

截图模式（`&cap=1`）走的是同一条路径：虚拟时间推不动 JS 弹簧，
不落终态就会截到上一帧的值（`usePrefersReducedMotion` / `hasCap()` 一起决定）。

**canvas 与 CSS 的失败都是静默的。** 画布拿到 `NaN` 的坐标时 `stroke()` 什么都不画、
也不报错；CSS 类名拼错同样没有任何提示，元素只是不动。两者都表现为「画面不对但控制台干净」。
**教训：先打印关键变量，再看画面** —— 不要靠肉眼看截图猜是布局问题还是取值为空。
