## 一、把「无用」写进 schema —— 用类型系统强制产品哲学

**问题**：产品要求首页那些效率数字「算不出来」。靠文案约束不可靠，
靠开发者自觉更不可靠——总有人会「顺手」加一个 `streak` 字段。

**方案**：让这件事在**类型和数据库层就做不到**，并用测试守住。

核心数据模型里没有任何可以用于排名的数值：

```ts
// app/src/features/memory/types.ts
export interface Entry {
  id: string
  kind: EntryKind          // 'sound' | 'photo' | 'word'
  createdAt: number
  text?: string
  durationMs?: number
  blobRef?: string         // 原始媒体在 blobs 表的 key，Entry 保持轻量
  tags: EntryTags          // 写入那一刻提取一次，不可回退的加工
  tagSource: TagSource     // 'llm' | 'rule' | 'seed'
}
```

数据库连表都不给它——3 分钟专注不落库，所以它没有资格拥有表：

```ts
// app/src/features/memory/db.ts
this.version(1).stores({
  entries: 'id, createdAt, kind, [kind+createdAt]',
  blobs: 'id',
  meta: 'key',
})
// 表结构里没有 focusSessions、没有 stats、没有 streaks。
```

写入路径也刻意不做任何可累加的事：

```ts
// app/src/features/memory/repo.ts
/**
 * 这里刻意不做的事：
 *  - 不累加任何计数（不存在「今天已记录 N 条」这种可累加的东西）
 *  - 不标记完成、不返回成就、不因为写入而改动别的条目
 */
export async function addEntry(draft: EntryDraft): Promise<Entry> {
  const entry: Entry = {
    id: createId(),
    kind: draft.kind,
    createdAt: draft.createdAt ?? Date.now(),
    tags: createEmptyTags(),
    // M1 还没接 LLM，如实标成 'rule' 而不是 'llm'——
    // 检索层将来要能分辨「这条标签是谁标的」，此刻撒的谎以后就追不回来了。
    tagSource: 'rule',
  }
  // ...
  await db.entries.put(entry)
  return entry
}
```

**守住这条线**的测试——它会在任何人试图加回效率字段时失败：

```ts
// app/src/features/memory/repo.test.ts
it('Entry 上不存在任何可用于「有用」的字段', async () => {
  const entry = await addEntry({ kind: 'word', text: 'x' })
  const forbidden = ['streak','completionRate','dailyGoal','done',
                     'completed','status','score','progress','count']
  expect(Object.keys(entry).filter((key) => forbidden.includes(key))).toEqual([])
})
```

> 类型系统里表达不出来的「有用」，界面上也就做不出来。

## 二、本地优先的记忆层与索引策略

**问题**：记忆检索要支持「按精确日期召回」（场景 C）和「跨条目计数」（场景 D）。
一个自然的冲动是上向量库 / 给所有标签建索引。

**方案**：两个决定——**写入时提取标签**（护城河），**检索时只用极简索引**。

索引只建在结构维度上：

```ts
// app/src/features/memory/db.ts
/**
 * 只索引 id / createdAt / kind / [kind+createdAt]。
 * 标签维度（themes / emotions / people / places）刻意不建索引——个人几千条封顶，
 * 内存过滤是微秒级；而为嵌套数组建 multiEntry 索引会让写入路径变复杂，
 * 还容易在标签更新时留下不一致的索引。复杂度花在"写入时提取标签"上更值。
 */
```

时间流只按时间倒序（`Entry` 上没有第二个可排的键），类型筛选走复合索引：

```ts
// app/src/features/memory/repo.ts
export async function listEntries(): Promise<Entry[]> {
  return db.entries.orderBy('createdAt').reverse().toArray()
}

/** 走 [kind+createdAt] 复合索引，不必把同类型条目全捞进内存再排。 */
export async function listByKind(kind: EntryKind): Promise<Entry[]> {
  return db.entries
    .where('[kind+createdAt]')
    .between([kind, Dexie.minKey], [kind, Dexie.maxKey])
    .reverse()
    .toArray()
}
```

原始媒体与条目分离，`Entry` 只留引用；删除时两者同事务清理，`meta` 保留
（否则每次启动都会重灌种子）：

```ts
export async function clearEntries(): Promise<void> {
  await db.transaction('rw', db.entries, db.blobs, async () => {
    await db.entries.clear()
    await db.blobs.clear()
  })
}
```

**为什么不做向量 RAG**：护城河在写入时的标签提取，不在检索算法。
两个最精彩的场景恰好是向量检索的盲区（精确日期、COUNT 聚合），
详见 [01 · 产品亮点](01-产品亮点.md#亮点六记忆检索不做向量-rag)。

## 三、真实录音：异步生命周期保护

**问题**：`MediaRecorder` + `getUserMedia` 是异步的，而 React 开发模式（`StrictMode`）
会把 effect 跑两遍（挂载 → 清理 → 挂载）。没有保护的话，**第一遍拿到的音频流会在
第二遍生效后继续偷偷录下去**。

**方案**：用 session 计数器给每一路取流打标记，过期的一路立即停掉。

```ts
// app/src/features/capture/useRecorder.ts
export function useRecorder() {
  const sessionRef = useRef(0)

  const start = useCallback(async () => {
    const session = ++sessionRef.current

    if (!navigator.mediaDevices?.getUserMedia) {
      setState('error')
      return
    }
    try {
      const stream = await navigator.mediaDevices.getUserMedia({ audio: true })

      // 这一路已经被取消了（组件卸载 / 又开了一次）
      if (session !== sessionRef.current) {
        stream.getTracks().forEach((track) => track.stop())
        return
      }

      const recorder = new MediaRecorder(stream)
      // ...
    } catch {
      if (session === sessionRef.current) setState('error')
    }
  }, [])
```

停止与取消是两条不同的路径——**取消什么都不留**：

```ts
  /** 组件卸载 / 换视图：丢掉这一段，什么也不留。 */
  const cancel = useCallback(() => {
    sessionRef.current++
    const recorder = recorderRef.current
    if (recorder && recorder.state !== 'inactive') {
      recorder.onstop = null      // 不给它机会产出 blob
      recorder.stop()
    }
    teardown()
    setState('idle')
  }, [teardown])

  useEffect(() => cancel, [cancel])   // 卸载即取消
```

取消路径把 `onstop` 置空，确保**丢掉的录音不会产生任何产物**——这既符合
「没用的事不留痕」，也避免了内存泄漏。

## 四、真实取景与「降级是设计的一部分」

**问题**：`getUserMedia` 需要安全上下文。http 局域网、被拒权限、没有摄像头都可能发生。
演示现场不能因为一个权限弹窗就黑屏。

**方案**：把「拿不到相机」当作一种正常状态，用 Canvas 画一片「窗外」顶上。

```ts
// app/src/features/capture/useCamera.ts
export type CameraState = 'idle' | 'live' | 'denied' | 'unavailable'

// 「有没有 getUserMedia」在渲染期就能判定，所以不放进 effect 里再 setState 一遍；
// effect 只负责真正去取流。
const supported = typeof navigator !== 'undefined' && Boolean(navigator.mediaDevices?.getUserMedia)

useEffect(() => {
  if (!active || !supported) return
  let cancelled = false
  let stream: MediaStream | null = null

  void (async () => {
    try {
      stream = await navigator.mediaDevices.getUserMedia({ video: { facingMode: 'environment' } })
      if (cancelled) { stream.getTracks().forEach((t) => t.stop()); return }
      if (videoRef.current) { videoRef.current.srcObject = stream; await videoRef.current.play() }
      setState('live')
    } catch {
      if (!cancelled) setState('denied')      // 如实降级，不假装成功
    }
  })()

  return () => { cancelled = true; stream?.getTracks().forEach((t) => t.stop()) }
}, [active, supported])
```

抽帧直接用 Canvas 从当前取景里抓一帧，转 JPEG Blob：

```ts
  const capture = useCallback(async (): Promise<Blob | null> => {
    const video = videoRef.current
    if (!video || !video.videoWidth) return null
    const canvas = document.createElement('canvas')
    canvas.width = video.videoWidth
    canvas.height = video.videoHeight
    const ctx = canvas.getContext('2d')
    if (!ctx) return null
    ctx.drawImage(video, 0, 0, canvas.width, canvas.height)
    return new Promise((resolve) => canvas.toBlob((b) => resolve(b), 'image/jpeg', 0.85))
  }, [])
```

降级画面不是一张静态图，而是用径向渐变「画」出来的窗景（`scene.ts`），
并且在列表缩略图里复用同一套配色，避免出现「另一种窗外」：

```ts
// app/src/features/capture/scene.ts
/** 照片缩略图用的同一套颜色，避免列表里出现另一种「窗外」。 */
export const SCENE_GRADIENT = [
  'radial-gradient(circle at 30% 25%,rgba(255,220,165,.55),transparent 60%)',
  'radial-gradient(circle at 72% 65%,rgba(255,180,110,.4),transparent 60%)',
  'linear-gradient(160deg,#232a3a,#3a332f 60%,#16161b)',
].join(',')
```

> 降级是设计的一部分，不是兜底补丁。

## 五、LLM 接入的形状与「剧本兜底是一等公民」

**问题**：黑客松最怕演示时 AI 没找到；同时 API Key 绝不能进客户端。

**方案**：三件事各就各位——**Key 留在服务端**、**客户端只认形状**、**没有 Key 就演剧本**。

Key 的唯一去处是开发中间件；无 Key 时如实返回，而不是报错：

```ts
// server/llmProxy.ts
/**
 * 存在的唯一理由：让 API Key 留在 .env.local 里，
 * 绝不出现在客户端代码或打包产物中。
 */
export function llmProxy(): Plugin {
  return {
    name: 'cike:llm-proxy',
    configureServer(server) {
      server.middlewares.use('/api/llm', (_req, res) => {
        res.setHeader('content-type', 'application/json; charset=utf-8')

        if (!process.env.LLM_API_KEY) {
          res.statusCode = 200
          res.end(JSON.stringify({ ok: false, reason: 'no-key' }))   // 如实告知
          return
        }
        // M4 在这里转发给 LLM_BASE_URL（OpenAI 兼容协议，通吃 DeepSeek / Kimi / 通义 / GLM）
        res.statusCode = 501
        res.end(JSON.stringify({ ok: false, reason: 'not-implemented' }))
      })
    },
  }
}
```

客户端只依赖一个**判别联合**的结果类型，不关心后端是模型还是剧本：

```ts
// app/src/features/agent/client.ts
export type LlmResult =
  | { ok: true; text: string }
  | { ok: false; reason: 'no-key' | 'not-implemented' | 'network' | 'bad-response' }

export async function askLlm(prompt: string): Promise<LlmResult> {
  try {
    const res = await fetch('/api/llm', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify({ prompt }),
    })
    if (!res.ok) return { ok: false, reason: 'bad-response' }
    return (await res.json()) as LlmResult
  } catch {
    return { ok: false, reason: 'network' }
  }
}
```

剧本把**台词与分支形状**钉死，与 Demo 逐句一致，接通时不用返工：

```ts
// app/src/data/script.ts
/** 演示里「提到这个项目 N 次」的 N。M3 接上聚合后由记忆层真实算出。 */
export const MENTION_COUNT = 7

/** 「8 月 17 日」那张记忆卡片。检索走的是精确日期，不是语义相似。 */
export const MEMORY_AT = new Date(2026, 7, 17, 21, 40, 0, 0).getTime()

export const OPENING_REPLIES: ScriptReply[] = [
  {
    label: '其实我还是想把这个项目做出来。',
    lines: [
      { say: '嗯。' },
      { say: `你已经提到这个项目 ${MENTION_COUNT} 次了。`, note: true },
      { say: '我猜，你不是不想做。' },
      { say: '那现在，要不要试 3 分钟？' },
    ],
  },
  // ...「我也不知道」分支会翻出 8 月 17 日的记忆卡片
]
```

**设计要点**：客户端 `reason` 是判别联合而非布尔——调用方能区分「没配 Key」
和「网络坏了」，将来做不同的 UI 反馈。而现在，两者都回落剧本，**演示不会失败**。

## 六、P0 叙事时序修正：从第一天就按正确语义长状态机

**问题**：原单文件版 `index.html` 在脚本末尾无条件执行 `aiStart()`，AI 全部对话
（含分支选项、最终「开始 3 分钟」按钮）在进入 App 后约 10 秒内就流完。
现场演示点「理解」时直接看到结尾，第五/六/七幕的转折全没了。

**方案**：把「进入 App」与「进入理解」在状态机层就分开。

```ts
// app/src/app/store.ts
/**
 * 「理解」的对话必须等你第一次点开这个 Tab 才开始。
 *
 * 原单文件版是进 App 就无条件跑完（index.html:1222），现场演示点进「理解」
 * 只剩结尾，第三幕的转折全没了。这是 P0 修正，所以状态机从第一天就按这个语义长。
 */
aiStarted: boolean

goPane: (pane) => {
  set({ pane })
  if (pane === 'ai') get().startAi()      // 只有切到「理解」才启动
},

startAi: () => {
  if (get().aiStarted) return            // 幂等：重复切 Tab 不会重放
  set({ aiStarted: true })
},
```

**同批修正的参考稿问题**（另见 `display.test.ts` / `lib/time.ts`）：

| 问题 | 修正 |
| --- | --- |
| AI 对话提前跑完（P0） | `aiStarted` 状态机，切到「理解」才启动 |
| 一句话输入 XSS / 破版 | 全程走 React 文本节点，不用 `innerHTML`；有测试守住尖括号原样保留 |
| 种子文案错字「地铁里有人在下雨。」 | 改为「外面在下雨。」 |
| 录音计时超 59 秒显示 `00:60` | `formatElapsed` 真进位，测试覆盖 `62:03` |

## 七、正确性细节

**时间格式**：只回答「这段声音多长」，不回答「你专注了多久」；录音计时真进位。

```ts
// app/src/lib/time.ts
/** 用于分组的稳定键：2026-09-25 */
export function dayKey(ts: number): string { /* ... */ }

/**
 * 时长文案。注意这里只回答"这段声音有多长"，不回答"你专注了多久"——后者不属于本产品。
 */
export function formatDuration(ms: number): string {
  const total = Math.max(0, Math.round(ms / 1000))
  if (total < 60) return `${total} 秒`
  const m = Math.floor(total / 60)
  const s = total % 60
  return s === 0 ? `${m} 分` : `${m} 分 ${pad2(s)} 秒`
}

/**
 * 录音计时：00:07 一路走到 01:23。
 * 原单文件版是 "00:" + pad(秒)，超过 59 秒会显示 00:60 / 00:61 —— 这里是真进位。
 */
export function formatElapsed(ms: number): string {
  const total = Math.max(0, Math.floor(ms / 1000))
  return `${pad2(Math.floor(total / 60))}:${pad2(total % 60)}`
}
```

**确定性伪随机**：波形的「随机」由下标算出来就够了，不引入真随机——
每次渲染都是同一张图，不因重渲染而抖动，也不违反 React 纯函数约定。

```ts
// app/src/lib/noise.ts
export function hash01(seed: number): number {
  const x = Math.sin(seed * 12.9898 + 78.233) * 43758.5453
  return x - Math.floor(x)
}
```

**object URL 生命周期**：`IndexedDB` 里的原图取出转 URL，卸载即 revoke；
且新旧引用切换时不闪上一张图。

```ts
// app/src/features/memory/useBlobUrl.ts
useEffect(() => {
  if (!blobRef) return
  let cancelled = false
  let created: string | undefined
  void getBlob(blobRef).then((blob) => {
    if (!blob || cancelled) return
    created = URL.createObjectURL(blob)
    setLoaded({ ref: blobRef, url: created })
  })
  return () => { cancelled = true; if (created) URL.revokeObjectURL(created) }
}, [blobRef])

return loaded && loaded.ref === blobRef ? loaded.url : undefined
```
