# 05 · 下一版方向定调：从仪表盘到个人时间感知系统

> **结论先行**：概念是新的，界面长得还是仪表盘。这一版动的不是功能清单，
> 而是四件事——**视觉焦点、核心动作、AI 形态、场景写法**。
> 首页从 Dashboard 换成一颗会随今天变化的球，主交互从「你想做什么」换成**攒元素 + 长按「记下此刻」**，
> AI 从聊天机器人换成「发现」，场景从情绪标签换成生活证据。
> 最终定位从「一个留下此刻的地方」升维为「个人时间感知系统」。

- 文档编号：05
- 状态：已落地并生效（`app/` 按本篇对齐）
- 适用对象：产品 / 设计 / 工程
- 上游依据：00 项目背景 · 01 产品亮点 · 02 需求文档

## 一、问题诊断：概念是新的，界面还是仪表盘

### 1.1 真正有价值的命题

不是帮助用户管理时间，而是让用户重新拥有 **「我可以选择如何使用时间」** 的感觉。

### 1.2 现状：焦点放错了

首页被故意做成「效率仪表盘」，并把**不可点击的 START FOCUS** 当作核心交互。
这在概念上很聪明，但在真实产品里会出问题。

用户打开首页第一眼看到的顺序是：

```
09:50  →  专注 / 完成率 / 连续天数  →  今日任务  →  START FOCUS
```

这串字与这些数字抢走的，是**错误的注意力**：它让人以为这里有一件事要完成。
理念写在别处，第一眼却在说另一件事。

> 所以问题不是「没有视觉焦点」，而是：**视觉焦点放错了。**

### 1.3 三个页面的共同问题

第二页（时间）已经变成普通的「时间线记录」；第三页（理解）又变成普通的 AI 对话。

**结论**：三个页面拆开看都成立，合起来却还没有形成一个「一眼只属于这个产品」的东西。

## 二、核心需求改写：拿掉「最后还是去做事」

### 2.1 现有链路

```
我不想做 → 停下来 → 留下一刻 → AI 理解 → 最后开始 3 分钟
```

这正是 02 需求文档「六层核心体验」所定义的路径。它的隐患是：
**最后还是回到了「做事」。**

虽然强调 3 分钟不计数、不留痕，但整个故事仍然是——
「一个不想工作的人，最后终于愿意工作了」。
这会把产品价值不知不觉拉回「一个劝你去工作的应用」。

### 2.2 建议改为

> 留下正在发生的生活 → 时间慢慢形成纹理 → AI 帮我重新看到那些
> 我自己没注意到的东西 → 我决定接下来怎么办。

**行动只是可能的结果之一，而不是产品终局。**

有时候最后是：

1. 我决定开始工作；
2. 我决定放弃这个项目；
3. 我发现自己其实很喜欢某件事；
4. 我意识到某段时间总在重复；
5. 我只是重新听到三个月前的一段雨声。

这时候，「无用」才真正成立。

## 三、三个方向，各用一部分

| 方向 | 用在哪 |
| --- | --- |
| **A · 时间场 / Time Field** | **首页** —— 一个正在变化的「时间生命体」，感知此刻 |
| **B · 时间考古 / Time Archaeology** | **产品核心** —— AI 从过去捞起一个被遗忘的瞬间 |
| **C · 无用花园 / Useless Garden** | **只借视觉语言** —— 不量化的生活资产 |

**不是三选一：A 做首页，B 做产品核心，C 只借它的视觉语言。**

> A 现在的落地形态是首页那颗网点球（见 [15](15-首页界面方案.md)）——
> 「会随今天留下的东西变化」这一条没变，变的是它的形状。

## 四、首页：推翻 Dashboard，立「此刻正在发生」

### 4.1 首页不再出现

- 专注
- 完成率
- 连续天数
- 今日任务
- START FOCUS

这些东西哪怕打叉、留白、不可点击，依然属于「效率产品的语言」。

### 4.2 新的唯一视觉中心

> 「此刻正在发生。」

屏幕中央是**一颗用网点画出来的球**。它不是装饰动画 —— 你今天留下的东西会慢慢改变它，
而**改变的方式只有一种：留下得越多，网眼越密**。

界面上一个数字都不写 —— 密度就是那个数字，只是它不可被计算。
「什么也不留」时球不动：不留也是一次留，但留的不是数据。

**这个形态一路收敛成「全 App 只有一颗球」**：它同时是首页的主体、理解页那枚 34px 头像、
拍照快门的面。

### 4.3 价值

产品第一次拥有一个真正属于自己的**视觉资产**。用户打开 App 第一眼不是看到功能，
而是看到「此刻正在发生」的**证据**。

而且它**不是柱状图，不是数字，不是统计**。

## 五、核心动作：从「你想做什么」到「攒元素 + 长按」

### 5.1 建议删除

> 「现在，你想做什么？ 想做 / 不想做」

这仍然逼用户先判断自己的状态。用户刚进来，为什么一定要回答「我想不想做事」？

### 5.2 新的自然动作

> **攒下此刻，然后长按落下。**

点文字 / 图片 / 声音各往那颗球上**攒**一个元素（落成绕球的小卡），
攒够之后**长按「记下此刻」**，攒下的全部一次落下——它们共享一个 `momentId`，
从此是**一件事**，不是三条记录。

这与「声音 / 照片 / 一句话 / 什么都不留下」的理念一致：三个真实入口都保留，
而「什么都不留下」收在右上角**一个安静的角**——它是完整的答案，
但不跟三个采集入口抢层级（见 [15](15-首页界面方案.md) §七）。

**处理方式：让「一次记录」成为一个事务。**

> 这一版最初定的是「按住此刻 → 四向刻度」，落地后收敛成了现在这个：一次只能留一样
> 东西，且「一件事」在数据上不存在。现方案见 [15](15-首页界面方案.md) §五。

## 六、AI：不做聊天机器人，做「发现」

### 6.1 现有损失

第三页目前最大的损失是：**AI 理念很特别，UI 却把它做成了聊天机器人。**

文档里本来定义得很好：

> AI 是「时间观察者 / 时间考古学家」，不是教练；它要看见当下、过去和关系。

那 UI 就不应该是一排排「AI 说一句 → 用户选一句 → 输入框」。这太普通了。

### 6.2 新形态：发现（Discovery）

- **不是每天汇报**；
- 它不主动推给你 —— 要看得自己走进「发现」。

用户点开后看到的**不是结论**（「最近你压力比较大」），而是**证据**：

> 9 月 3 日，23:47 —— 你留下了一段洗衣机的声音。
>
> 9 月 11 日，00:18 —— 你写：「终于没人找我了。」
>
> 昨天，23:52 —— 你什么也没写，只录了 31 秒窗外。

然后 AI 只说一句：

> **这三次，你都在所有人安静以后才留下东西。**

再问：

> **这是一天里唯一真正属于你的时间吗？**

这才有「被认出来」的感觉。

## 七、场景写法：不要情绪标签，要生活证据

### 7.1 现有场景的问题

「我又不想工作了」「坐咖啡店看窗外」「今天风很大」「这个项目提了 7 次」——
这些都太像产品经理为了证明功能写出来的场景。现有 A–D 四个场景基本都围绕
「不想工作 → 理解 → 重新开始」，指向过于单一。

### 7.2 新原则

> **不要写「情绪标签」，写生活证据。**

| ❌ 不要 | ✅ 而要 |
| --- | --- |
| 我今天好焦虑。 | 凌晨 00:26。电梯停在 17 楼。我在门口站了两分钟才进去。 |
| 我不想工作。 | PPT 打开了四十分钟。我一直在改第一页标题的字号。 |
| 今天很幸福。 | 儿子洗澡时在里面唱了一首完全听不懂的歌。我站在门外录了 18 秒。 |

### 7.3 由此得到一条新设计原则

> **不要保存用户已经知道的结论。**
> 保存那些「当时不知道为什么值得留下，后来才知道」的东西。

## 八、下一版定义：个人时间感知系统

### 8.1 命名与话术

产品只说自己**是什么**，不说自己不是什么；甚至「无用」都不要在每一屏反复说。
「无用」可以继续作为**品牌哲学**，但用户真正感受到的应该是：

> **时间不是一串被花掉的数字。**
> **它是一些正在发生、以后可能重新被理解的东西。**

### 8.2 页面职责分工

| 页面 | 职责 |
| --- | --- |
| 此刻（首页） | **感受到它** —— 三个入口留下它，长按一次落成 |
| 时间 | **重新遇见它** |
| 发现 | **把它收起来** —— AI 把相关的记录聚成一册一册的档案 |
| 理解 | **找回线索** —— 说出大概，它把相关的记录翻出来 |

「行动只在真的出现时提供」贯穿四屏，不是一个单独的页面。

### 8.3 升维结论

| 现在 | 下一版 |
| --- | --- |
| 一个留下此刻的地方 | **个人时间感知系统** |

这条路比现在高一个层级，而且 UI 也因此真正有机会做到惊艳——
而不是给一个 Dashboard 换皮。
