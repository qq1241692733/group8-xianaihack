# 03 · 技术架构

## 一、技术选型与版本

工程 `app/` 为 Vite + React + TypeScript strict。版本**钉死**，不用 `^` 浮动：

| 类别 | 选型 | 版本 | 为什么是它 |
| --- | --- | --- | --- |
| 框架 | React | 19.3.0 | — |
| 构建 | Vite | 8.3.1 | 开发体验快，插件生态足够 |
| 语言 | TypeScript | **5.9.3** | 见下方「为什么锁 5.9.3」 |
| 状态 | Zustand | 5.0.15 | 全局状态少，不需要 Redux 的仪式感 |
| 本地库 | Dexie | 4.4.6 | IndexedDB 的薄封装，支持复合索引 |
| 校验 | Zod | 4.6.5 | 将来解析 LLM 返回的严格 JSON |
| 测试 | Vitest | 5.0.2 | 与 Vite 同源，配置零成本 |
| Lint | ESLint | 10.11.0 | 含 `typescript-eslint` 8.70.1、react-hooks、react-refresh |

**为什么 TypeScript 刻意锁 5.9.3 而不是最新版**：`typescript-eslint`（含 latest 与
canary）的 peer 上限是 `typescript < 6.1.0`，升 TS 之前得先等它放开，否则 lint 工具链
装不上。这是**工具链约束**，不是偏好。

## 三、分层与数据流

```
              ┌─────────────────────────── 界面层 ───────────────────────────┐
              │ screens/（此刻·时间·理解）  app/（壳层·浮层）  features/*/ 组件  │
              └───────────────┬───────────────────────────┬──────────────────┘
                              │ 读 entries / captured      │ 写 draft
                              ▼                            ▼
              ┌──────────────────────── store.ts（Zustand 唯一真源）────────────┐
              └───────────────┬───────────────────────────┬──────────────────┘
                              │ listEntries                │ addEntry
                              ▼                            ▼
              ┌──────────────────── features/memory ──────────────────────────┐
              │  repo.ts（读写）   types.ts（数据模型）   display.ts（文案）      │
              │  db.ts（Dexie 三表：entries / blobs / meta）  useBlobUrl.ts      │
              └───────────────────────────┬───────────────────────────────────┘
                                          ▼
                              ┌──── IndexedDB（纯本地，原音原图不出设备）────┐
                              └───────────────────────────────────────────┘

     采集路径：features/capture（MediaRecorder / getUserMedia）→ EntryDraft → store.capture() → repo
     AI 路径：features/agent/client.ts → POST /api/llm → server/llmProxy.ts → LLM
              失败 / 无 Key → 回落 data/script.ts（剧本兜底，一等公民）
```

**一句话**：界面只与 `store` 打交道；`store` 只与 `features/memory/repo` 打交道；
原始媒体只有 `blobs` 表碰得到。**没有任何一条路径能把原音原图送出去。**

## 四、模块职责

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| `app/store.ts` | 全局状态：当前 Tab、浮层、entries、captured、AI 是否已启动 | 唯一真源；`aiStarted` 状态机修正 P0 叙事时序 |
| `features/memory/types.ts` | 数据模型 `Entry` / `EntryTags` / `EntryDraft` | **把「无用」写进类型**：无 streak / completionRate / done |
| `features/memory/db.ts` | Dexie 三表与索引 | 无 focusSessions 表；标签维度刻意不建索引 |
| `features/memory/repo.ts` | 条目的增删查 | 写入不累加任何计数、不产生成就 |
| `features/memory/display.ts` | 列表/卡片主副文案 | 绝不出现「已完成」「第 N 天」 |
| `features/capture/useRecorder.ts` | 真实录音 | session 计数器保护异步生命周期 |
| `features/capture/useCamera.ts` | 真实取景 + 抽帧 | 失败进 `denied`，界面降级 |
| `features/capture/scene.ts` | 相机不可用时的「窗外」画面 | 降级是设计的一部分 |
| `features/agent/client.ts` | 问后端要一句话 | 返回 `no-key` 时调用方回落剧本 |
| `server/llmProxy.ts` | 开发期代理 | **API Key 只在这里**；无 Key 返回 `{ok:false,reason:'no-key'}` |
| `data/script.ts` | 剧本台词与分支 | 与 Demo 逐句一致 |
| `lib/time.ts` | 时间格式化 | 只回答「这段声音多长」，不回答「你专注了多久」 |

## 五、持久化设计

三张表，各自有明确边界：

| 表 | 主键 / 索引 | 存什么 | 不存什么 |
| --- | --- | --- | --- |
| `entries` | `id, createdAt, kind, [kind+createdAt]` | 轻量条目（文本、时长、标签、blobRef） | 原始媒体、任何统计字段 |
| `blobs` | `id` | 原始音频 / 图片 Blob | — |
| `meta` | `key` | 种子是否已灌等元信息 | — |

**索引策略**：只索引 `id / createdAt / kind / [kind+createdAt]`。标签维度
（themes / emotions / people / places）**刻意不建索引**——个人记录几千条封顶，
内存过滤是微秒级；而为嵌套数组建 `multiEntry` 索引会让写入路径变复杂，还容易在
标签更新时留下不一致的索引。**复杂度花在「写入时提取标签」上更值。**

时间流只按 `createdAt` 倒序——`Entry` 上没有第二个可排的键，所以做不出排行榜。
按类型筛选走 `[kind+createdAt]` 复合索引，不必把同类型条目全捞进内存再排。

## 六、状态管理

只有一个 Zustand store。要点：

- `entries`：全量（含种子），三个屏共用。
- `captured`：**只在本次会话里新留下的**。首页那条虚线只看它，且它不进任何统计。
- `refuseCount`：START FOCUS 被拒次数，驱动三句台词递进。
- `aiStarted`：**「理解」的对话必须等你第一次点开这个 Tab 才开始**。

最后一条是 P0 修正：原单文件版进 App 就无条件跑完整场 AI 对话，现场演示点进「理解」
只剩结尾，转折全没了。所以状态机从第一天就按正确语义长。

## 七、隐私边界

```
┌─ 设备内 ───────────────────────────────┐   ┌─ 设备外 ────────────────┐
│  原始音频 / 图片 → IndexedDB blobs 表   │   │  仅「文本 + 标签」→ LLM  │
│  文本 / 标签 → IndexedDB entries 表     │   │  API Key → .env.local   │
└────────────────────────────────────────┘   └─────────────────────────┘
```

1. **原音原图永不出设备**：`Entry` 只留一个 `blobRef`，Blob 本体存 `blobs` 表；
   将来喂给 LLM 的只有提取出的文本与标签。
2. **API Key 永不出服务端**：客户端 `fetch('/api/llm')` 打到开发中间件，
   Key 由 `server/llmProxy.ts` 从 `process.env` 读取。无 Key 时如实返回 `no-key`，
   客户端回落剧本——**不会因为没配 Key 而演示失败**。
3. `.env.local` 已被 `.gitignore` 忽略。

## 八、样式架构（三层）

| 层 | 文件 | 内容 |
| --- | --- | --- |
| 令牌层 | `styles/tokens.css` | 颜色 / 字体 / 圆角 / 缓动 + 全局 `@keyframes`；**颜色的唯一来源** |
| 原子层 | `styles/atoms.css` | 跨屏复用的排版与控件原子（`.eyebrow` / `.keepBtn` / `.chip` / `.empty` …） |
| 全局层 | `styles/global.css` | 重置、`body` 氛围、手机外壳层 |

组件内部一律用 **CSS Modules**，组件里**不允许出现字面色值**，只能引用令牌。

`tokens.css` 末尾尊重系统设置，动画在 `prefers-reduced-motion: reduce` 下全部退化为静态：

```css
@media (prefers-reduced-motion: reduce) {
  :root * { animation-duration: 0.001ms !important; transition-duration: 0.001ms !important; }
}
```

> 产品不给奖励，也不该给人添麻烦。

## 九、构建 / 测试 / 运行

```bash
# 本机 npm 不在 PATH，需用完整路径调用 npm-cli.js（详见工程约定）
npm run dev        # 本地开发（http://localhost）
npm run dev:host   # 局域网访问，自动挂自签证书（手机调试 getUserMedia 必需）
npm run typecheck  # tsc，无输出即通过
npm test           # vitest run
npm run build      # tsc && vite build
```

**为什么 `--host` 要挂自签证书**：麦克风/相机（`getUserMedia`）要求安全上下文。
localhost 天然满足，但手机走 `http://<局域网IP>` 会被浏览器直接拒绝。
本地 localhost 仍走 http，免掉自签证书告警：

```ts
// vite.config.ts
const useHttps = process.argv.includes('--host')
plugins: [react(), llmProxy(), ...(useHttps ? [basicSsl()] : [])]
```

**测试环境**：Vitest + `fake-indexeddb`，因此 IndexedDB 相关的仓储测试不需要浏览器。
当前 2 个测试文件、18 个用例全部通过。
