# 03 · 技术架构

> 技术选型、目录结构、分层与数据流、状态管理、样式架构、隐私边界与演示捷径。
> **技术内容一律以 [`app/`](../app/) 的真实代码为准**，不以任何一份方案文档为准。
> 界面长什么样见 [15](15-首页界面方案.md) / [17](17-四屏界面方案.md) —— 本篇讲**代码怎么分层**。

## 一、技术选型与版本

工程 `app/` 为 Vite + React + TypeScript strict。版本**钉死**，不用 `^` 浮动：

| 类别 | 选型 | 版本 | 为什么是它 |
| --- | --- | --- | --- |
| 框架 | React | 19.3.0 | — |
| 构建 | Vite | 8.3.1 | 开发体验快，插件生态足够 |
| 语言 | TypeScript | **5.9.3** | 见下方「为什么锁 5.9.3」 |
| 状态 | Zustand | 5.0.15 | 全局状态少，不需要 Redux 的仪式感 |
| 本地库 | Dexie | 4.4.6 | IndexedDB 的薄封装，支持复合索引 |
| 校验 | Zod | 4.6.5 | 解析 LLM 返回的严格 JSON |
| 测试 | Vitest | 5.0.2 | 与 Vite 同源，配置零成本 |
| 测试环境 | fake-indexeddb | 6.2.5 | 仓储测试不需要浏览器 |
| Lint | ESLint | 10.11.0 | 含 `typescript-eslint` 8.70.1、react-hooks、react-refresh |

**为什么 TypeScript 刻意锁 5.9.3 而不是最新版**：`typescript-eslint`（含 latest 与
canary）的 peer 上限是 `typescript < 6.1.0`，升 TS 之前得先等它放开，否则 lint 工具链
装不上。这是**工具链约束**，不是偏好。

## 三、分层与数据流

```
        ┌──────────────────────────── 界面层 ────────────────────────────┐
        │ screens/（此刻·时间·发现·理解）  app/（壳层·浮层）  features/*/组件 │
        └──────────────┬────────────────────────────┬────────────────────┘
                       │ 读 entries / discoveries    │ 写 draft / 手势动作
                       ▼                             ▼
        ┌─────────────── store.ts（Zustand 唯一真源）────────────────────┐
        └──────────────┬────────────────────────────┬────────────────────┘
                       │ listEntries                 │ addEntry
                       ▼                             ▼
        ┌──────────────────── features/memory ───────────────────────────┐
        │ repo（读写，含 addMoment）types（模型）display（文案）extract（写入时提取）│
        │ query（标签检索 + expandToMoments）aggregate（读时聚合）        │
        │ db（Dexie 五表）  useBlobUrl                                    │
        └────────────────────────────┬───────────────────────────────────┘
                                     ▼
                        ┌──── IndexedDB（纯本地，原音原图不出设备）────┐
                        └──────────────────────────────────────────────┘

采集路径：features/capture（MediaRecorder / getUserMedia）→ EntryDraft
          → store.stageDraft()（攒着，不落库）→ 长按 → store.commitMoment() → repo.addMoment()
          （整组共享一个 momentId；单张相册导入仍走 store.capture() → repo.addEntry）
绘制路径：store.entries → MomentScreen（密度级 = levelOf + 攒着的件数）
          → useMomentStage（rAF + 弹簧）→ dotOrb.DotOrb.render（网点球，逐帧合成）
发现路径：store.entries → data/discoveries（判据 match → expandToMoments 带回整个「此刻」）
          → buildDiscoveries → DiscoverScreen
AI 路径：features/agent/client.ts → POST /api/llm → server/llmProxy.ts → LLM
          失败 / 无 Key → 回落 FALLBACK_LISTEN（data/script.ts，一等公民）
```

**一句话**：界面只与 `store` 打交道；`store` 只与 `features/memory/repo` 打交道；
原始媒体只有 `blobs` 表碰得到。**没有任何一条路径能把原音原图送出去。**

## 四、模块职责

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| `app/store.ts` | 全局状态：当前板块、浮层、entries、攒元素暂存区（`staged`）、discoveries、collections、会话（`sessions` / `sessionId`）、AI 队列 | 唯一真源；`aiQueue` 由 `useAiQueue` 在理解页挂载时排空 |
| `features/timefield/dotOrb.ts` | 网点球：`drawDotOrbTexture` 铺网（静态头像与动态首页**同源**）；`DotOrb` 管呼吸 / 按下 / 进食 / 变密 | 色板分昼夜（`ORB_THEME`），亮暗部从 `--c1`/`--c2` 读；随机是确定性的 `mulberry32`，不在渲染期取时间 |
| `features/timefield/useMomentStage.ts` | rAF 主循环 + 建球 + 密度（记录数 + 攒着的件数） | 每帧不 setState，只画球 |
| `features/timefield/holdController.ts` | 长按 900ms 的判定 | **纯逻辑、可注入时钟**；三条独立的路（rAF / 定时器 / 松手墙钟），缺一条后台标签页就提交不了 |
| `features/timefield/SatelliteLayer.tsx` | 攒下的元素绕球三个方向的小卡 | 坐标与球心同源；计数与槽位计数器分开 |
| `features/timefield/evidence.ts` | 记录数 → 密度级 | **纯函数**；密度是唯一一处「数量影响界面」，且不出现数字 |
| `features/memory/types.ts` | 数据模型 `Entry` / `EntryTags` / `EntryDraft` | **把「无用」写进类型**：无 streak / completionRate / done |
| `features/memory/db.ts` | Dexie 五表与索引 | 无 focusSessions 表；标签维度与 `momentId` 刻意都不建索引 |
| `features/memory/repo.ts` | 条目的增删查 + `addMoment`（一个事务写下共享 `momentId` 的整组） | 写入不累加任何计数、不产生成就；整组失败一起回滚 |
| `features/memory/query.ts` | 标签检索 + `expandToMoments`（命中一条带出整个「此刻」） | 纯函数、内存过滤，与守望复用同一匹配面 |
| `features/memory/extract.ts` | 写入时标签提取（本地词典） | 词典不含评价性 / 成就性词 |
| `features/memory/aggregate.ts` | 读时聚合与精确日期检索 | 全部纯函数，`Entry` 上永远不多一个字段 |
| `features/memory/display.ts` | 列表 / 卡片主副文案 | 绝不出现「已完成」「第 N 天」 |
| `data/discoveries.ts` | 发现卡的判据表与成卡逻辑（`cardFromDef` 唯一成卡；自建合集经 `collectionCardFrom` 复用） | **存判据不存死数据**；跨度必须等于真实起止 |
| `data/collections.ts` | 自建合集：`listCollections` / `addCollection` / `removeCollection` | 存用户挑的 `entryIds` **快照**（不是判据）；与守望「现算」刻意相反 |
| `features/agent/sessions.ts` | 会话归档：`loadSessions` / `saveSessions` / `sessionTitle` | localStorage `cike:sessions`，上限 20；Blob 只留 `blobRef` 字符串 |
| `data/script.ts` | 台词原语（`SayPart` / `ScriptLine` / `t`）+ 回落句 `FALLBACK_LISTEN` | 完整剧本已删；回落是一等公民 |
| `lib/stage.ts` | 演示与截图捷径（查询参数） | 不改产品逻辑 |
| `server/llmProxy.ts` | 开发期代理 | **API Key 只在这里**；无 Key 返回 `{ok:false,reason:'no-key'}` |
| `lib/time.ts` | 时间格式化 | 只回答「这段声音多长」，不回答「你专注了多久」 |

## 五、持久化设计

五张表，各自有明确边界：

| 表 | 主键 / 索引 | 存什么 | 不存什么 |
| --- | --- | --- | --- |
| `entries` | `id, createdAt, kind, [kind+createdAt]` | 轻量条目（文本、时长、标签、`blobRef`、可选的 `momentId` / `meta`） | 原始媒体、任何统计字段 |
| `blobs` | `id` | 原始音频 / 图片 Blob | — |
| `meta` | `key` | 种子是否已灌等元信息 | — |
| `watches` | `id, createdAt` | 用户立过的守望词 | 守望产出（册每次现算） |
| `collections` | `id, createdAt` | 用户自建合集（`name` + 用户挑的 `entryIds` 快照） | — |

**Dexie 版本沿革**：v1 = `entries` / `blobs` / `meta`；v2 = `watches`；v3 = `collections`。

**索引策略**：只索引 `id / createdAt / kind / [kind+createdAt]`（`collections` 也只用
`id, createdAt`，**不索引 `entryIds`**）。标签维度
（themes / emotions / people / places）**刻意不建索引**——个人记录几千条封顶，
内存过滤是微秒级；而为嵌套数组建 `multiEntry` 索引会让写入路径变复杂，还容易在
标签更新时留下不一致的索引。**复杂度花在「写入时提取标签」上更值。**

`momentId` 同理**不建索引**：一次「此刻」的元素屈指可数，展开在内存里做
（`query.expandToMoments`）。要为它建索引就得升 Dexie 版本，眼下没有这个必要。

时间流只按 `createdAt` 倒序——`Entry` 上没有第二个可排的键，所以做不出排行榜。
按类型筛选走 `[kind+createdAt]` 复合索引，不必把同类型条目全捞进内存再排。

**不落库的东西**：3 分钟专注、以及 `discoveries` / `keptDiscoveries`
（发现卡每次从真实记录现算，所以它永远不可能和库存不一致）。

### localStorage 键清单

界面／会话状态走 `localStorage`，统一 `cike:` 前缀：

| 键 | 存什么 |
| --- | --- |
| `cike:composer` | 采集浮层里未发出的草稿 |
| `cike:llm` | 用户自填的 LLM 端点配置 |
| `cike:theme` | 昼夜主题选择（`?theme=` 可盖过它） |
| `cike:sessions` | 归档的历史对话（`Session[]`，上限 20，超了丢最旧） |

**Blob 永不落 `localStorage`**：记录里只有 `blobRef` 字符串，真正的音视频／图片数据
只在内存与 `blobs` 表里（与 §七 隐私边界同一条线）。

## 六、状态管理

只有一个 Zustand store。要点：

- `pane`：`'moment' | 'time' | 'discover' | 'ai'` 四个板块。
- `entries`：全量（含种子），四个屏共用；`captured` 保留但首页不再单列。
- `staged`：**攒着、还没落下的元素**（文字 / 图片 / 声音的 draft + 一点点预览）。
  攒在 store 而不是组件里，因为采集浮层与首页是兄弟节点，浮层够不到首页的局部 state。
  同时由 store 管照片 object URL 的生命周期（`stageDraft` 建、`unstage`/`clearStaged` 撤销）。
- `captureIntent`：点首页三个入口进来时，浮层直接落在哪一屏（`sound` / `photo` / `word`）——
  没有「先选一个」的中转态。
- `discoveries` / `keptDiscoveries` / `promotedId`：用户自己按下的「更新到发现」，
  以及已保留的卡（保留之后固定，不被后续整理挤掉）。
- `collections`：自建合集（Dexie `collections` 的镜像）。
- `sessions` / `sessionId`：归档的历史对话（`cike:sessions`）与当前所在的那一段——
  「新增对话」把当前这段先归档、再开新的。
- `aiQueue`：待浮现的消息留在 store 里 → 切 Tab 不丢、可以续播；
  由 `useAiQueue` 在「理解」这一屏挂载时才排空。

`aiQueue` 这条是 P0 修正的产物：原单文件版进 App 就无条件跑完整场 AI 对话，现场演示点进
「理解」只剩结尾，转折全没了。所以队列从第一天就按「等你进这一屏才播」的语义长。

## 七、隐私边界

```
┌─ 设备内 ───────────────────────────────┐   ┌─ 设备外 ────────────────────────┐
│  原始音频 / 图片 → IndexedDB blobs 表   │   │  文本 + 标签 → LLM               │
│  文本 / 标签 → IndexedDB entries 表     │   │  （可选）512px 去 EXIF 缩图 → LLM │
│  API Key → 服务端 .env.local            │   └─────────────────────────────────┘
└────────────────────────────────────────┘
```

1. **原音原图默认不出设备**：`Entry` 只留一个 `blobRef`，Blob 本体存 `blobs` 表。
   文本与标签本来就走 LLM。
   **唯一的例外是「让 AI 看一眼画面」这个开关**（默认关，需显式打开）：
   打开后照片会被缩到 512px、JPEG 重编码（`toDataURL` 天然剥掉 EXIF 与 GPS）再发出去。
   这是全项目**唯一**让记录离开设备的地方，来龙去脉见 [24](24-打标与检索.md) §四。
2. **API Key 永不出服务端**：客户端 `fetch('/api/llm')` 打到开发中间件，
   Key 由 `server/llmProxy.ts` 从 `process.env` 读取。无 Key 时如实返回 `no-key`，
   客户端回落到 `FALLBACK_LISTEN`——**不会因为没配 Key 而演示失败**。
3. `.env.local` 已被 `.gitignore` 忽略。

## 八、样式架构（三层）

| 层 | 文件 | 内容 |
| --- | --- | --- |
| 令牌层 | `styles/tokens.css` | 颜色 / 字体 / 圆角 / 缓动 + 全局 `@keyframes`；**颜色的唯一来源** |
| 原子层 | `styles/atoms.css` | 跨屏复用的排版与控件原子（`.eyebrow` / `.chip` / `.empty` …） |
| 全局层 | `styles/global.css` | 重置、`body` 氛围、手机外壳层 |

组件内部一律用 **CSS Modules**，组件里**不允许出现字面色值**，只能引用令牌。

**令牌的当前口径**：

- **一屏只有一个彩色主体**：首页那颗球。它是蓝的（`--c1` / `--c2`），
  **不做色相插值** —— 空与满的差别只用**网点密度**表达（见 [15](15-首页界面方案.md) §三）。
- **强调色只有一个金 `--warm`**，只出现在：**发现页卷内的「已保留」** ·
  **时间页筛选的选中态** · **开场那一点温度** · **首页攒够之后那句提示与入口上的计数徽章**。
  > 攒下的卫星卡**不上金** —— 它用的是中性卡面；长按按钮的进度也只是把按钮底色提亮一档。
  > 筛选选中态是**视图状态**，不占用「一屏一处金」那个额度。
- 四个方向色 `--d-voice` / `--d-photo` / `--d-write` / `--d-blank` 是四向罗盘时代的遗产，
  罗盘退场后只剩 `--d-voice` 还有消费方（「听见」那条声波），另三个已无引用。
- 冷青降级为底雾（`--cool` 只作极低透明度的一层），不再是配色的一半。
- 记录类型色 `--kind-sound` 只用在发现页卷内的声波条上，不参与混合。
- 小字对比度：`--ink-3` 夜版提到 0.58、昼版压到 `#6f6f76`（低于 4.5:1 的小字在真机上看不见）。

`tokens.css` 末尾尊重系统设置：`prefers-reduced-motion: reduce` 下全部动画与过渡退化，
画布那边的弹簧直接落到终态、呼吸停止（见 `usePrefersReducedMotion.ts`）。

> 产品不给奖励，也不该给人添麻烦。

## 九、构建 / 测试 / 运行

```bash
# 本机 npm 可能不在 PATH，用托管 Node 的完整路径调用：
#   C:/Users/guope/.workbuddy/binaries/node/versions/22.22.2-3/npm.cmd
npm run dev        # 本地开发（http://localhost）
npm run dev:host   # 局域网访问，自动挂自签证书（手机调试 getUserMedia 必需）
npm run typecheck  # tsc，无输出即通过
npm run lint       # eslint，0 问题
npm test           # vitest run
npm run build      # tsc && vite build
```

**为什么 `--host` 要挂自签证书**：麦克风/相机（`getUserMedia`）要求安全上下文。
localhost 天然满足，但手机走 `http://<局域网IP>` 会被浏览器直接拒绝。
本地 localhost 仍走 http，免掉自签证书告警：

```ts
// vite.config.ts
const useHttps = process.argv.includes('--host')
plugins: [react(), llmProxy(), ...(useHttps ? [basicSsl()] : [])]
```

**测试环境**：Vitest + `fake-indexeddb`，因此 IndexedDB 相关的仓储测试不需要浏览器。
对账测试是质量门：`seed.reconcile` / `discoveries.reconcile` / `repo` / `evidence`
——**演示里的每个数字（提到 7 次、8 月 17 日、发现卡跨度）都必须能从库存里数出来**。
（原先的 `script` 对账测试随剧本一起删了。）

**界面自检**：`lib/stage.ts` 提供演示捷径，配合无头浏览器截图核对终态。
注意 `--virtual-time-budget` **等不到 IndexedDB**（虚拟时间只快进定时器与 rAF），
要用 CDP + 真实等待；工具见 `tools/cdp-shots.cjs`。

| 参数 | 作用 |
| --- | --- |
| `?stage=field` | 跳过开场，直接看首页 |
| `?stage=staged` | 跳过开场，并在首页攒好三件（一句话 / 一段声音 / 一张照片） |
| `?stage=time` / `discover` / `understand` | 跳过开场，直接进对应板块 |
| `&cap=1` | 关掉过渡并把弹簧写进终态——**仅供无头截图核对**，真实浏览器不需要 |
| `&theme=day` / `night` / `system` | 强制主题，盖过 `localStorage` |
