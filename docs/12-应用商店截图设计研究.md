# 12 · 应用商店截图设计研究

> 素材：微信收到的 `前端ui设计3(1).wps`。**里面没有一页是文档，103 张全是图。**
> 规格统一为 1260 × 2844（iPhone 15 Pro / 14 Pro 的 @3x 全屏尺寸）。
> 本页是对这批素材的**研究记录**，只服务于「此刻」的商店页 / 路演截图 / 官网配图，
> **不改任何现行定调**——设计定调基准仍在 [05](05-下一版方向定调.md)，
> 配色以 `app/src/styles/tokens.css` 与 [15](15-首页界面方案.md) / [17](17-四屏界面方案.md) 为准。

## 一 这份素材到底是什么

文件后缀是 `.wps`，本体是 OLE 复合文档：正文流只有 **104 个字符**（全是图片占位符），
而 `Data` 流有 **49 MB**——也就是说，作者把 103 张截图一张张插进了一个空文档里。

每张图的构成完全一致：

| 区域 | 内容 |
| --- | --- |
| 上部 | 画廊的灰底（`#797979`） |
| 中部 | 真正的设计卡片，纵向占全图 **58%–85%**（平均 80%），左右满宽 |
| 下部 | 深色工具条，**× / 裁切 / 播放** 三个键 |

底部那三个键说明了一件事：**这批图是从某个设计灵感画廊上逐张截屏收下来的**，
不是设计源文件。所以能学到的是**成品套路**，不是分层稿。

> **2026-09-26 修订**：逐张量过内部设计图的实际长宽比之后，本页原先"103 张 App Store
> 商店截图"的说法要收窄——只有四成是竖屏机截图：
>
> | 内部设计图形态 | 张数 | 占比 |
> | --- | --- | --- |
> | 竖屏机截图（≥ 1.9） | 42 | 41% |
> | 方版（0.9–1.4） | 29 | 28% |
> | 横版（< 0.9） | 23 | 22% |
> | 竖版卡（1.4–1.9） | 9 | 9% |
>
> 准确说法是**通用界面设计灵感集**。本页 §一的结构描述（画廊底 + 中部设计图 + 底部工具条）
> 与后面的配色 / 构图统计仍然成立，只是"商店页成品"这个定性不严谨。
> （当时据此写过一份「素材借鉴与 UI 匹配」的方案，已归档到 `_archive/docs/14-素材借鉴与UI匹配方案.md`。）

> 顺手记一个可复现的提取方法：`.wps` 本体是 OLE，用 `olefile` 打开 →
> 扫 `Data` 流里的 `FFD8FF` 签名 → 按下一个签名截断 → 103 张全部可解。
> 成品图放在 `docs/shots/refs-appstore/`。

## 二 全量总览

先看全局。103 张按顺序平铺，编号即文件名里的序号：

![103 张横铺总览，编号对应 docs/shots/refs-appstore/AS-编号.jpg](shots/refs-appstore/_00-总览.jpg)

一眼能读出来的三件事：

1. **绝大多数是"一台手机 + 一块底色 + 一句话"**，而不是复杂的信息图。
2. 深色底和浅色底势均力敌，但**纯白底很少**。
3. 同一个 App 的画面**几乎都在讲同一件事**，没有一张试图在一屏里塞完所有功能。

## 三 配色：六成是中性色

对每张图的**卡片区域**（自动剔除画廊灰底）做了加权主色统计：

| 主色调 | 张数 | 占比 |
| --- | --- | --- |
| **中性（黑 / 白 / 灰）** | **64** | **62%** |
| 蓝 | 9 | 9% |
| 红 / 棕 | 8 | 8% |
| 黄 | 6 | 6% |
| 紫 / 品红 | 6 | 6% |
| 绿 | 4 | 4% |
| 青 | 3 | 3% |
| 橙 / 琥珀 | 3 | 3% |

| 卡片明度 | 张数 | 占比 |
| --- | --- | --- |
| 浅（> 0.68） | 8 | 8% |
| 中（0.42–0.68） | 53 | 51% |
| 偏暗（0.22–0.42） | 14 | 14% |
| **深（< 0.22）** | **28** | **27%** |

三条结论，都可以直接拿来做决策：

**① 中性底色是主流，彩色是少数派。** 62% 的卡片主色落在黑白灰区间。
彩色底只占 38%，而且**一次只给一个色相**——没有一个 App 在商店页里同时用蓝 + 绿 + 橙。

**② 深底靠"一点彩光"救活，不是靠面积。** 深色/偏暗合计 41%。
这些图的共同做法是：大面积近黑，然后在一个位置留**一小块高饱和的点光**
（比如 #030 是一台暖橙界面、#051 是一圈蓝色光弧）。
如果没有那一点，黑底截图会和 App Store 深色模式的页面底色连成一片，卡片边界直接消失。

**③ 纯白底反而最少（8%）。** 白底最省事，但在这批样本里是少数——
因为白底在手机上会"发光"，且边界感弱；用浅灰（`#F1F1F1` 一档）比纯白更稳。

## 四 六个可复用的构图模板

下面六张是**六个模板各取一个代表**，编号与素材一一对应：

![六个构图模板的代表：013 满屏沉浸 / 018 单机居中 / 030 双机景深 / 056 大标题压顶 / 078 无设备编辑式 / 092 卡片堆叠](shots/refs-appstore/_选样-6.jpg)

### 模板 A · 单机居中 + 大留白

代表 **#056**、#018、#041、#042。浅灰底，手机居中偏下，**顶部一行大标题**
（"Flight Status"），标题左侧对齐、字号大约是屏宽的 6%–8%。
手机与顶栏之间留出一整屏 1/6 的空白，让标题能呼吸。

> **适合**：功能明确、一句话说得清的工具型 App。下载转化最稳的一种。

### 模板 B · 满屏沉浸 + 无边框

代表 **#013**、#015、#051、#053、#069。设计本身铺满整屏，**不画手机边框**，
常常配深色底或大渐变。 #013 的做法尤其典型：紫色渐变底 + 几块彩色圆角卡片岛屿，
中央一条播放器，左下角一组巨号数字 `03:41`。

> **适合**：气质型产品。读者第一眼看到的是"氛围"，不是"功能"。

### 模板 C · 多机并列 + 分组叙事

代表 **#030**、#014、#024、#082–#086。两到三台手机并排：
一台讲"现在"，一台讲"历史"；或者一台主界面 + 一台详情。
#030 还叠了一层**景深**——前景清晰、后景虚化，让两台机器有前后关系而不是平贴。

> **适合**：功能成组出现、需要"对比着看才明白"的产品。**每台只讲一件事**，不要两台讲同一件。

### 模板 D · 手持实拍 + 真实场景

代表 **#103**、#023、#020、#038。一只手拿着手机，背景是真实环境（桌面 / 街景 / 织物）。
画面立刻从"渲染图"变成"有人在用"。

> **适合**：需要建立"这是给真人用的"信任感时。注意：背景一定要虚化，否则手机看不出来。

### 模板 E · 文字即主视觉 + 超大字号

代表 **#092**、#095、#097、#067。让巨号标题 / 数字占掉版面的一半，
手机反而退成配角。#092 是一叠**斜向堆叠的卡片压在虚化人像上**，
#067 是一张奶油色票根上压一句衬线大字。

> **适合**：品牌调性 > 功能说明的时候。留白多、字大、信息少，反而记得住。

### 模板 F · 无设备 + 编辑式

代表 **#078**、#066、#064、#060。**画面里没有一台手机**，只有海报、书页、画廊般的版式。
#078 是白底上两栏并列（左 "SAVION" / 右 "TAME IMPALA"），
#066 是 "CASES / ABOUT" 的杂志式跨页。

> **适合**：当产品本身就是"内容容器"（阅读、相册、记忆类）时，
> **不放手机反而更能说明它是什么**——这一条对「此刻」特别重要。

## 五 反复出现的六个细节动作

1. **保留 iOS 状态栏和灵动岛。** 103 张里几乎每一台手机都带着时间、信号、电量。
   这不是懒——保留状态栏 = "这是真机上的样子"，比剔干净更有说服力。
2. **只写一句话。** 标题 + 一行副题，极少数有第三行。副题通常在 12 个词以内。
3. **标题压在手机上方或侧上方**，不与手机中心对齐——错开一格，视线会先读字再看机。
4. **深底必留一点彩光。** 见第三章 ②。
5. **景深虚化 + 悬浮。** 手机 / 卡片不贴底，带阴影和虚化，产生"浮在纸上"的层次。
6. **底图用真实照片，不用纯色。** 织物、皮肤、木纹、街景——哪怕虚化到只剩质感，
   也比纯色底更"贵"。

## 六 落到「此刻」：五张商店截图脚本

「此刻」的处境和这批样本里任何一个都不一样：**它是一款"没有数字"的 App**。
商店页如果按常规套路写"专注计时 / 效率提升"，就自己把自己拉回了普通番茄钟。
所以脚本的原则是——**每一张截图只负责击碎一个预期**。

配色沿用昼版的令牌：纸白 `#FDFDFC`、四层灰、**唯一的颜色只给那颗网点球**。
夜版（`#090D13` 的墨蓝黑）留给路演大屏 —— 两套值都在 `tokens.css` 里，见
[15](15-首页界面方案.md) §八。

| # | 模板 | 画面 | 标题 | 击碎什么 |
| --- | --- | --- | --- | --- |
| 1 | **F 无设备** | 白纸一片，正中一颗网点球（密度=今天的记录量），下方一行小字 | 「时间不是用来管理的」 | 这不是效率工具 |
| 2 | **F 无设备** | 三个入口并列：文字 / 图片 / 声音；「什么也不留」收在角落 | 「你只需要留下此刻」 | 不记录也是一种答案 |
| 3 | **A 单机居中** | 首页原样（那颗会随时间变密的球），**一个数字都没有** | 「它不会给你打分」 | 没有完成率、没有连续天数 |
| 4 | **C 多机并列** | 同一屏分三段：三条证据 + 一句观察（先材料、后结论） | 「它把你留下的时刻，重新讲给你听」 | AI 不是教练，是镜子 |
| 5 | **E 文字即主视觉** | 纯文字海报，一句衬线大字压满版面 | 「原音原图，永不出设备」 | 隐私即卖点 |

**首图（第 1 张）不要放手机。** 这一条是这批素材里最反直觉、也最值得抄的：
在 #011、#013、#092 这些记忆点最强的样本里，**手机都不是主角**。
「此刻」首图如果只放一颗球，反而在一屏里就说清了"我和你见过的那些 App 都不一样"。

## 七 素材位置与复现

| 内容 | 路径 |
| --- | --- |
| 103 张成品图（760 宽，共 7.1 MB） | `docs/shots/refs-appstore/AS-001.jpg` … `AS-103.jpg` |
| 全量总览（带编号） | `docs/shots/refs-appstore/_00-总览.jpg` |
| 六模板选样 | `docs/shots/refs-appstore/_选样-6.jpg` |
| 原始 .wps | 微信文件目录 `前端ui设计3(1).wps`（49 MB，未入库） |

复现提取（已脚本化，不需要装 Office / WPS / LibreOffice）：

```bash
P="C:/Users/guope/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
"$P" tools/ole-extract.py "微信目录/前端ui设计3(1).wps" docs/shots/refs-appstore \
     --width 760 --quality 80 --text
```

原理：`.wps` = OLE 复合文档 → `olefile` 按流读 → `WordDocument` + `0Table` 走 FIB / Clx
piece table 出正文（本例只有 104 字符）→ 在 `Data` 流里扫 `FFD8FF` 位图签名、
按下一个签名截断、Pillow 解不开的丢弃。本次实测输出 103 张，与肉眼计数一致。

> 顺带一个坑：旧版 `.wps` 走「本地文档通道」会被按 magic bytes **误判成表格**，
> 然后报 `No workbook open`；正文流里也确实没有内容可读。这类"外面是文档、里面是图"
> 的文件，直接解 OLE 反而又快又稳。
