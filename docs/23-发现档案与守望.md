# 23 · 发现档案与守望（发现重设计 + 「帮我发现」）

**这一篇是发现页的现行方案，加新功能「帮我发现」（守望）的定调**
（重设计已于 2026-09-27 落地，落点见 §六）。
用户判断放在最前面，因为它们是这一稿的起点：

1. **重设计前的发现页与时间页结构太像** —— 时间页是按天分组的纵向列表，发现页是竖轴
   加挂卡，两者都是「自上而下的一条流」。骨架一样，换皮没用。
2. **不像一个档案** —— 发现应该是「AI 把一个事件相关的文字、图片、声音记录在
   一起」，点开是一个有艺术感和结构感的界面。
3. 「档案」是形容**集合**的词，**不是格式** —— 所以不要卷宗编号、不要公文表头、
   不要文件夹隐喻。档案说的是「这些记录被收在一起了」，仅此而已。

## 一 发现 = 档案

### 一册是什么

**一册 = AI 把一个事件/场景相关的记录聚成的集合**，里面可以同时有声音、照片、
一句话。它不是一条记录的放大，也不是一个分类，是 AI 看出「这些记录说的是同一件事」
之后，替你收在一起的一沓。

- 册名：AI 起的短名（「半夜的声音」「孩子的九月」），点名字可以直接改。
- 不给计数、不给日期跨度数字：封面与卷内**不出现「N 条」「09.10 — 09.26」**。
  时间只以一个词出现（「九月」）。这是 17 §四「先材料，后结论」的反向修正：
  保留「从记录里数出来、不写文案」的诚实原则，但**不再把数摆出来** —— 不可让渡
  三条里「不给数字」对这一屏同样生效，而且集合的大小让封面自己说（波形的高低、
  照片的多少、留白的多少），比一个数字诚实。
- 不给结论：册上那句（「都是大家睡了以后留下的。」）是**证据的引子**，不是判断。
  「先材料，后结论」的顺序不变，只是材料的单位从「卡」升成了「册」。

### 册架：与时间页的分界

| | 时间 | 发现（新） |
| --- | --- | --- |
| 是什么 | 你的账本：一条一条 | AI 替你收的：一册一册 |
| 单位 | 一条记录 | 一册集合 |
| 排列 | 按天分组，小行密排 | 大封面稀排，一屏约一册半 |
| 打开 | 行即全部，没有下钻 | 卷内页：编排过的证据 |
| 骨架 | 向下的列表流 | **没有轴、没有流**，只有面上的堆叠 |

节奏是两屏真正的分界：时间页密、小、匀；册架疏、大、**每册高度刻意不等**——
集合与集合本来就不一样重。竖轴和节点（17 §四）**已退场**，
「节点随条数变重」的物理化表达由封面材质的疏密接管。

### 封面：材质从内容里长出来

封面不做统一模板 —— 三种册，三种封面，材质取自它收的东西：

1. **声音册**：波形是封面的地平线。固定几何（每次渲染都变形的波形不是证据，
   是噪音——沿用 DiscoverScreen 的老规矩），纸面上走 `rgba(16,16,18,.30)` 的暗线。
2. **照片册**：一截照片条。真图直接排；拿不到图时沿用 `scene.ts` 降级画面的语言
   （浅灰阶渐变 + 一处光斑），不画空心方块充数。
3. **文字册**：原句就是封面主体，衬线大字，不套卡片。

封面上唯一的状态标记是**守望来源**：右上角一枚线性眼睛 + 「留意着」，
不上色（三屏只有一个金色落点的纪律不变，金留给卷内「保留」的回执）。

### 卷内：打开一册

![发现 · 卷内](shots/23-dossier.jpg)

结构感的来源是**类型各得其所**，段与段之间只有细线和大留白，没有表头：

- **声音 → 成列**：每行「时间 · 它是什么 · 时长」加一条通栏波形。
- **照片 → 成条**：横向排开，不裁成统一方格。
- **一句话 → 成引文**：衬线大字独立成段，前后大留白。

段落只在该册真有此类记录时出现——这册没有照片，就不出现照片段。
**编排是自动的**（用户说的「预览自动整理」）：AI 按上面的骨架排好，用户不参与排版。

底部三件事：

- **保留**：金只在这一下出现（按下后「已保留」）——金是动作回执，不是装饰。
- **改名**：点册名直接改，AI 起的名字是草稿不是定稿。
- **解散**：这一册散回时间页，**记录一条不少**——档案是聚合视图，不是搬运。

页脚一句出处：「这一册，是从你留下的记录里长出来的。」

### 册架的顶部：「正在帮你留意」

守望在发现页有一个**常驻显影**（`watchStrip`），在标题副题下面：

> 👁 正在帮你留意：孩子 · 想不到的声音　　　　设置

- **为什么放在这一屏**：这一屏的气质不用金句说——守望条本身就是气质：
  它替你留意着，而你不必做任何事。「生长」的意思由条里的「正在」二字承担，
  比一句形容词更实。守望的产出（册）全在这里，它的存在就该在这里可见。
- **点开就是它的设定与管理**（浮层「帮我留意」）：守望词 chips（每条尾巴一个安静的 ×，
  删除即失效、不留痕）+ 一句话添加（输入框占位「想让我总替你留意什么？」）。
  设定原本住在理解页，2026-09-27 搬到了这里——**设定是偶尔做的事，不该占着理解页一屏**；
  入口与产出同页，两边都看得见，没有暗处的规则。
- 展示形式安静：`--fill` 底、ink-2 文字、ink-4 的「设置」去向提示。不上色，
  不抢封面的戏。间距上贴标题，与首册之间拉开——它是页首的一部分，不是内容之间的隔断。

### 单类型与自由组合

一册可以是三种记录的**任意组合**：声音+照片、照片+一句话、三样都有，也可以只有
一样——专收声音的人，他的册里就只有声音。呈现不为此发明新形态，靠三条规则自动成立：

1. **卷内段落按类型出现，顺序固定：声音 → 照片 → 一句话。** 从证据到人的顺序，
   不按数量排（数量是排名）。段只在该册真有此类记录时出现——组合是数据，
   呈现是类型驱动的确定性模板。
2. **封面材质 = 主导类型。** 主导类型在内部按占比取（平手时照片 > 声音 > 文字，
   照片最有封面相），**界面永不显示占比**。
3. **单类型册不显示段头。** 全册只有一种类型时，唯一的段不必再自报家门——
   没有分节的需要。这时卷内是一整列它自己：纯声音册是一整列声纹，
   纯照片册是相接的整条，纯文字册是引文组。

| 组合 | 卷外（封面材质） | 卷内 |
| --- | --- | --- |
| 只有声音 | 波形地平线 | 一整列声纹（无段头） |
| 只有照片 | 胶片条 | 照片相接成整条（无段头） |
| 只有一句话 | 原句即封面 | 引文组，每句独立成段（无段头） |
| 声音 + 一句话 | 波形地平线 | 声纹列 + 引文段 |
| 照片 + 一句话 | 胶片条 | 照片段 + 引文段 |
| 声音 + 照片 | 波形地平线 | 声纹列 + 照片段 |
| 三样都有 | 主导类型的材质 | 声纹列 + 照片段 + 引文段 |

![卷内 · 纯声音](shots/23-solo.jpg)

只记录声音的用户，他的册架上每一册都是波形地平线——**这不是缺了照片的残缺形态，
是他收藏本来的样子**，像黑胶收藏家的架子上全是唱片。单类型反而最纯：呈现层对
「缺一种类型」不做任何补偿，不拿别的类型凑、不画空段、不写「还没有照片」。

## 二 帮我发现 = 守望

### 问题与答案

需求：有人爱记录特定场景——队员总记录孩子，有人专收声音：植物的、动物的、
想不到的声音。这是**常驻**需求，不是一次性的查询，所以它是一个**长期的设定**。

「让用户自己设置，还是让 AI 在理解里懂自己、形成习惯？」——**两层都要，但主从分明**：

1. **显式设定是主体。** 守望清单在发现页「帮我留意」浮层里，随时可见、可加、可删。
   它的产出（册）就在同一屏消费——**设定入口与产出同页**（设定是偶尔做的事，
   所以收进浮层，不占理解页一屏）。
2. **对话是入口之一，且提议必须确认。** AI 在理解对话里可以说「你最近留下的
   一半是夜里的声音，要我替你留意『想不到的声音』吗？」——但 AI **永远不能
   默默替用户立约**。用户按下「好，替我留意」的那一刻，守望才成立。

这就同时回答了「怎么约束」：**隐式是入口，显式是事实**。AI 只有一票提议权，
确认权永远在用户手里；守望清单本身全部可见，没有任何藏在暗处的规则。

### 交互形态

![守望 · 设定与管理](shots/23-watch.jpg)

- **设定与管理在发现页的「帮我留意」浮层里**：守望词 chips（「孩子」「想不到的声音」），
  每条尾巴一个安静的 ×（删除即失效，不留痕）；下方一句话添加。
  浮层里那句话把边界写在界面上：**「它不提醒你，也不催你。只在你留下的时候，
  替你聚起来。」**
- **设定动作是一句话，不是表单。** 没有勾选框、没有分类下拉。用户在输入框里
  写「孩子」两个字就够了——输入框占位是「想让我总替你留意什么？」。
- **提议 → 确认**（AI 提议分支尚未做）：AI 提议以对话形式出现在**理解页**，
  配「好，替我留意 / 先不用」两个并列按钮（并列出口的老原则：拒绝同样是完整结果）。
  确认后守望浮层里多一行，对话里回一句「好。我不提醒你——只是你留下的时候，把它聚起来。」

### 五条硬边界（这一功能的全部约束）

1. **守望不说话。** 不推送、不提醒、不说「你很久没记录孩子了」。它只改变发现页
   的聚合优先级。一句催促就会把这个产品变成提醒 App——这是最不能破的一条。
2. **提议必须确认。** AI 不能默默设立守望；没有用户按下的那一下，就不存在。
3. **没有完成态。** 不显示「已守望 N 天」，没有打卡、没有断档、没有进度。
   守望词不是任务，是留意。
4. **只聚不改。** 守望只影响发现页的聚合，不碰首页（球不因守望变色）、
   不碰留下记录的手势、不碰时间页。
5. **撤回无痕。** 删掉一条守望，相关册保留（它们已经是「聚出来的」），
   但不再继续聚合；界面上不出现任何「你删掉了」的回执。

### AI 的自主权：给在「生成」侧，确认权留在「保留」侧

给 AI 一定的自主权，但自主权的形态是确定的：**AI 的产出一律以草稿存在，
草稿没有有效期、不催处理，不理它 = 它安安静静躺在那儿。**

| | 内容 |
| --- | --- |
| **AI 可自主**（生成侧，静默做） | 召回与成册判定 · 册名与引子句草拟 · 守望提议的**发起** · 记忆压缩的蒸馏 |
| **必须用户按下**（保留侧） | 守望成立（提议 → 确认）· 册的保留（金的回执）· 改名生效 · 解散 |
| **永不做** | 推送、催促、打分 · 改首页与留下记录的手势 · 删除或搬运记录 · 在用户未确认时把任何草稿转正 |

这样 AI 有做事的自由，用户有不理它的自由：册可以永远不解散也不保留，
名字可以永远不改，提议可以永远不答——系统不因此给任何压力。
自主权不是「AI 替用户决定」，是「AI 替用户把草稿先做好」。

### 守望的持久化与记忆压缩

守望是 agent 的第一个**跨会话状态**，由此引出 agent 记忆的分层设计：

- **原始层（永不压缩）**：记录（entries）+ 对话流水，全在本地 IndexedDB。
  压缩永远不碰这一层——原始记录完整可回放，这是隐私与诚实的底线。
- **工作层（压缩对象）**：`agentMemory` —— AI 对用户的认识：守望史、成册史、
  对话里蒸馏出的要点。每条限长、总量有上限。
- **压缩怎么跑**：条数或体积阈值触发 → 旧要点 + 新事件交 LLM 蒸馏成新的要点集
  （JSON 结构化输出）→ 写回工作层。**压缩失败就不压**——宁可不压缩，
  不可压丢；没有 LLM 时产品照常运转（工作层只是 prompt 的素材，不是数据本身）。
- **压缩的用途**：`buildFreeTextPrompt` 的 digest 从「手工 tally 计数」升级为
  「压缩层要点 + 最近几条原文」，上下文体积有界，AI 越用越懂你而不是越用越慢。

### 册架标题与文案

- 标题：**「发现」**；副题：**「零散的记录，慢慢有了联系。」**——册是长出来的：
  你留下，它聚合，册自己长大；这句话就是它的说法，不再另添金句。
- 标题下是**「正在帮你留意」条**（§一）：页首因此多一处真实功能，而非一行形容词。
- 出处行（卷内页脚）：「这一册，是从你留下的记录里长出来的。」

### 三个场景

1. **队员**：守望「孩子」。两周里留下的照片、录音、一句话被聚成「孩子的九月」，
   封面是照片条。他打开卷内，照片成条、她的声音成列——没有人给他报数。
2. **女朋友**：守望「想不到的声音」。某晚楼道里的猫、冰箱的低鸣、雨棚上的雨点
   聚成「半夜的声音」，封面是波形地平线。守望浮层里那句话告诉她：她不用记得
   「该记录了」，留下的东西自己会聚。
3. **AI 提议**：用户在理解里说「我好像总在录声音」。AI 回：「你最近留下的，
   一半是夜里的声音。要我替你留意『想不到的声音』吗？」——好 → 守望成立；
   先不用 → 对话继续，什么都不发生。

## 三 对话返回册（理解页，2026-09-27 已落地·本地路由版）

用户在理解页说话：「把夜里的声音整理一下」（整理）、「我留意过哪些声音？」（查询）——
对话要能返回**一册或多册**。对话流不是阅读空间，塞进去的是回执，不是册本身。

### 原则：对话给回执，阅读在发现

对话里**永远不渲染完整卷内**。册的节奏、留白、材质是发现页的空间；
消息流里给的是**回执**——材质缩影 + 册名 + 期间，够认出这一册，就停。

### 两种意图 × 两种回执，动作由状态决定

| 意图 | 例句 | 典型返回 | 回执状态 | 动作 |
| --- | --- | --- | --- | --- |
| 整理 | 把夜里的声音整理一下 | 单册回执 | **草稿**（还不存在） | 留下 / 不要 |
| 查询 | 我留意过哪些声音？ | 多册回执 | **已有**（在架上） | 翻开来 |

两个意图都可能返回单册或多册——回执形态跟着内容走，不跟意图走。
关键的一刀：**动作由状态决定，不由意图决定**。

- 草稿的动作是「留下 / 不要」——AI 只有一票提议权（§二自主权原则在对话里的落地），
  「留下」按下才有金回执（「它在发现的第一册」），「不要」则散了就散了，
  如实回一句「它们都还在原地」；
- 已有的动作是「翻开来」——引路去发现页卷内，不存在确认问题，也不许出现「保留」
  （它本来就在架上）。

同一个回执组件承载两个状态，视觉差异只在草稿底部的一行小字：
**「这一册还不存在 —— 留下它才在。」**

### 单册回执

- 材质缩影（波形 38px ／照片条 ／引文一行）——与封面同一套材质语言，只是矮；
- 册名 + 期间（起止日期，**不报条数**——发现页不给数字的纪律同样管着对话）；
- 草稿多一行**聚合缘由**（「都发生在夜深以后的家里。」）——「为什么是它们」
  在对话侧是硬要求（草稿必须交代），卷内维持出处行不变（§七 待定项 4 的答案）；
- 草稿态的册名与缘由用 ink-3，是「还没定」的语气。

### 多册回执

- **册架的缩影**：行列表，每行 = 材质小缩略（36px）+ 册名 + 期间；
- 不报总数——AI 说「替你找到了这些」，列表可滚，不写「共 N 册」；
- 点一行**原地展开**成单册回执（不跳页、不丢对话上下文），
  展开后「翻开来」才离开对话去发现页。

### 技术落点

- 消息类型：`AiMessage` 加 `{ kind: 'volume', card, draft }` 与
  `{ kind: 'volumes', cards }`——回执复用 `DiscoveryCard`，`draft` 是**消息**的属性，
  不进卡的数据（同一张卡在架上就不是草稿了）；
- 意图路由（`routeVolumeIntent`，本地先判、可测试）：**查询**（**不走 LLM**：已有册 +
  关键词／材质命中，确定性）→ **整理**（命中册出草稿／已有回执；LLM 两步成册另走两条链）；
  都没命中返回 `null`，交给自由输入那一路（`useFreeText`：LLM，失败回落
  `FALLBACK_LISTEN`——不假装自己答过了）；
- 输入框占位是**轮播灰字**（「我想找⋯」「不必记得是哪一天。」…）；
  路由的歧义由本地判定吸收，不推给用户措辞。

## 四 技术与分工：哪些固定，哪些交给 AI

多变的形式**不能靠 AI 排版**——AI 排的版每次都不一样，那不是档案，是抽卡。
分工按「承重 / 装饰」一刀切开：

| 层 | 归属 | 内容 |
| --- | --- | --- |
| **召回**：哪些记录可能属于一册 | **固定，本地代码** | tags 命中、同 scene、时间邻近、守望词文本匹配；命中之后再把同一次「此刻」的元素一起带出（`expandToMoments`，见 [24](24-打标与检索.md) §五）。记录不出设备，离线可跑，可测试 |
| **成册判定**：这几条真是同一件事吗 | **AI，可回退** | 本地召回候选组 → LLM 看脱敏摘要（时间、类型、tags、文字原句），答「是 / 不是 + 册名 + 引子句」，**JSON 结构化输出** |
| **册名 / 引子句** | **AI 生成，可改可省** | 失败回落：册名 = 期间词+类型（「九月的声音」），引子句省略（出处行已有） |
| **卷外材质 / 卷内骨架** | **固定** | 类型驱动的确定性模板；波形固定几何；颜色令牌。AI 不产出任何布局 |
| **守望提议与确认协议** | **AI 提议，代码立约** | AI 只有一票提议权；「好，替我留意」按下之前，什么都没发生 |
| **对话意图路由 + 查询已有册** | **固定，本地代码** | 意图本地判定（守望/查询/整理/闲聊），查询走已有册 + 关键词命中，确定性（§三） |
| **整理成册的对话回执** | **AI 草拟，可回退** | 两步成册的产物以草稿回执返回，「留下」才转正（§三） |

回落链是完整的：LLM 全挂 → 判据聚合照常出册 → 册名走期间词+类型 → 引子句省略。
**AI 是装饰层，不是承重层**——沿用「回落兜底是一等公民」的现有哲学
（`features/agent/freeText.ts` 的 FALLBACK_LISTEN 同理）。

## 五 agent 架构现状（审计）与三个已补的最小能力

现状盘点（`app/src/features/agent/` + `server/llmProxy.ts`，2026-09-27 审计）：

| 能力 | 有无 | 现状 |
| --- | --- | --- |
| LLM 通道 | ✅ | OpenAI 兼容代理（`server/llmProxy.ts`，Key 只在 `.env.local`），16 类失败分类 + 60s 超时；**但只有单轮纯文本**：一条 prompt 进、一段 text 出，无 messages 历史、无流式 |
| 兜底 | ✅ | **完整剧本已删**（理解页改成找回线索的落地页）：`data/script.ts` 只剩台词原语（`SayPart` / `ScriptLine` / `t`）+ `FALLBACK_LISTEN` 回落句；消息由 `useAiQueue` 驱动；LLM 失败即回 `FALLBACK_LISTEN` |
| 上下文构建 | ✅ | `prompt.ts` 把真实记录算成 digest（计数 + 最近几条）组装进 prompt。手工字符串，无 RAG |
| 判据聚合 | ✅ | `discoveries.ts`：本地确定性成卡，是唯一成卡逻辑 |
| 结构化输出 | ❌ | 模型返回自由文本，靠 `sanitizeReply` 清洗限长 |
| 工具调用 | ❌ | LLM 不能选数据、不能触发动作；数据选择全在本地 |
| agent 持久状态 | 🟡 | 守望（`watches`，Dexie）与**对话会话归档**（`cike:sessions`，localStorage，上限 20）已持久；`agentMemory` 压缩层仍未做 |
| MCP / skill / 多步规划 | ❌ | 无，也**不需要**——没有多步任务，每一步都是一次判定 |

**结论：这不是 deepagent 架构，也不该是。** 产品的三条硬约束——记录不出设备、
离线可用、演示现场确定性——决定了正确形态是「**本地聚合承重 + LLM 薄装饰 +
回落兜底**」。为档案与守望要补的三个最小能力，**均已完成**：

1. **结构化输出** ✅：`features/agent/llmJson.ts`。
2. **两步成册** ✅：本地召回候选组（`features/agent/dossier.ts`）→ LLM 判定
   （同一件事？册名？引子句）→ 回落照旧。LLM 全程不接触原始音频／照片 blob。
3. **守望持久化** ✅：`data/watches.ts`（Dexie v2），agent 的第一个跨会话状态。

## 七 还没定的事

   待定的是 AI 起名的口径（从记录里的词长出名字，还是「九月的声音」这种
   期间词 + 类型的组合）。
