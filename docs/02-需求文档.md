# 02 · 需求文档

## 一、目标与非目标

### 目标

把「无用 → 感知 → AI → 有用」这条体验**证明出来**。第一版不做完所有设想，
只要评委/用户走完一遍能理解产品哲学即可。

### 非目标（明确不做）

复杂社交 · 排行榜 · 连续打卡 · 复杂任务管理 · 完整健康数据 · 复杂商业化 ·
过度复杂的 AI Agent 多工具调用。

> 这些不是「以后再做」，而是**与产品命题冲突**：任何制造绩效压力的机制都不进来。

---

## 二、六层核心体验

| 层 | 用户状态 | 产品行为 | 核心交互 |
| --- | --- | --- | --- |
| 第一层 · 反效率 | 我不想做 | 解除即时绩效压力 | 不可用的 START FOCUS |
| 第二层 · 停下来 | 那就先不做 | 允许存在 | 「什么都不做」全屏空间 |
| 第三层 · 留下此刻 | 留下一个声音/画面/念头 | 让时间可回到 | 声音 / 照片 / 一句话 / 空白 |
| 第四层 · 重新感知 | 我正在经历什么？ | 重新获得当下 | 时间流（触感而非数字） |
| 第五层 · AI 理解 | 为什么我总在这里停下来 | AI 帮助看见自己 | 三段式回应 |
| 第六层 · 自主行动 | 我想开始 | 提供足够小的行动入口 | START 3 MIN（首次真正可用） |

---

## 三、核心场景（验收用例）

**场景 A｜「我又不想工作了」**
用户产生逃避感 → 点「我不想干了」→ App 不批评：「好，那就先不做。」
→ 录下 15 秒办公室空调声 → AI 不要求总结，只保存 → 几天后发现模式 →
问「你是真的不想做，还是害怕开始？」
> 价值：从自责 → 感知 → 理解，而不是从自责 → 更强的自律。

**场景 B｜「我什么都没做的一小时」**
坐在咖啡店看窗外 → 传统工具计入低效时间，本产品只留下声音与一句话「今天的风很大。」
→ 三个月后重听，重新回到当时。
> 价值不是生产力，而是时间的可回溯性与生活感。

**场景 C｜AI 帮你找回曾经的自己**
用户说「最近感觉什么都做不好。」→ AI 不立即给建议，而是从时间档案里找到相关瞬间：
「你还记得 8 月 17 日吗？」→ 播放当时的风声、展示照片和一句话。
> 价值：AI 不替用户创造情绪，而是帮用户找回已经存在过的经验。

**场景 D｜终于想做了**
AI 发现用户连续多次提到同一项目 →「你已经提到它 7 次了。我猜你不是不想做。
要不要陪你开始 3 分钟？」→ 用户点击 START 3 MIN，这个按钮第一次真正可用。
> 价值：从外部绩效驱动，转向内在意义驱动。

> 场景 C 与 D 正是「不做向量 RAG」的技术动因，见
> [01 · 产品亮点](01-产品亮点.md#亮点六记忆检索不做向量-rag)。

## 四、信息架构与功能分区

### 三个 Tab

| Tab | 内容 | 工程实现 |
| --- | --- | --- |
| **此刻** | 伪装成效率仪表盘的首页；大数字全是 `—`；最大的按钮按不动；仅提供「想做 / 不想做 / 留下一刻」 | `screens/MomentScreen.tsx` |
| **时间** | 时间流，按「声音 / 照片 / 一句话」筛选，每条都是触感而非数字 | `screens/TimeScreen.tsx` |
| **理解** | AI 三段式回应（让你看见当下 → 重新看见过去 → 理解自己），最后才是行动 | `screens/UnderstandScreen.tsx` |

### 四个全屏浮层（Overlay）

| 浮层 | 内容 | 工程实现 |
| --- | --- | --- |
| **开场** | 进入 App 前的引子 | `app/Intro.tsx` |
| **什么都不做** | 呼吸圆环不设时长、不会完成 + 环境声音缓慢浮现；想走随时可以走 | `features/nothing/NothingOverlay.tsx` |
| **留下此刻** | 声音 / 照片 / 一句话 + 「什么都不留下」（四者同等显眼） | `features/capture/CaptureOverlay.tsx` |
| **3 分钟专注** | 从「我必须完成」变成「这是我真正想做的」；用完不留痕、不进时间流 | *待实现（M2）* |

## 五、关键 UI / 交互需求

1. **首页数据不构成价值判断**：用「今天，你拥有 2 小时 47 分钟」，
   不用「今天浪费了 2 小时 47 分钟」。
2. **状态式入口**：核心入口应是「现在，你想做什么？」而不是传统任务按钮，
   两个方向「想做」「不想做」。
3. **不想做之后**：进安静的「此刻」界面（不批评、不推动）。
4. **想做之后**：只有用户表达明确的内在意愿时，才进入「要不要陪你开始 3 分钟？」，
   此时 START 3 MIN 才真正可点击。

**交互原则**：按钮不是所有时候都可用 · 系统状态随用户心理状态改变 ·
不可用本身就是表达 · 可用本身就是产品叙事 · 少做解释，让交互让用户自己理解。

## 六、AI Agent 需求

**角色**：一面温和的镜子，不是效率教练。三层能力：看见当下 / 看见过去 / 看见关系。

**核心 Prompt 思想**：

> 你不是一个效率教练。你是一面温和的镜子。你的任务不是让用户变得更有用，
> 而是帮助用户看见自己。当用户没有行动意愿时，不推动；当用户开始表达真正的意义
> 与愿望时，再提供一个足够小的行动入口。

**输出原则**：先观察不评价 · 先提问不说教 · 先帮助理解自己再给建议 ·
不制造新的绩效压力 · 不替用户决定什么是有用。

**兜底要求（硬性）**：黑客松最怕「演示时 AI 没找到」。因此**剧场兜底是一等公民，
不是补丁**——没有 Key、请求失败、模型返回不可解析，一律回落到 `data/script.ts`
的剧本，分支与 Demo 逐句一致。

---

## 七、隐私与伦理需求

1. 声音、照片和文字属于高度个人化的生活数据，MVP 应明确告知用户如何存储与处理。
2. **能本地完成的分析优先本地完成。**
3. AI 不应该给用户贴心理疾病、人格等标签。
4. AI 的观察应表达为「我注意到……」而不是「你就是……」。
5. 用户可以随时删除单条记录或全部时间档案。

## 九、设计裁决规则（有争议时按这几条判断）

1. 有用的事不留痕迹，无用的事才被留下来。
2. 不给进步，只给存在。
3. 不做评价，只做回应。
4. **不可用本身就是表达。**
5. **任何需要「完成」的东西都是 bug。**
6. 不是不让你行动，而是不替你决定为什么行动。
