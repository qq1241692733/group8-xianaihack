# 01 · 产品亮点

> **无用 = 记录当时，你不知道它有什么用。**
>
> 不是一句文案，而是贯穿数据层、交互层、文案层的一条设计约束。下面六个亮点，
> 每一条都能在 `app/` 里找到对应的代码或类型来兜底。
>
> 叙事总纲见 [00](00-项目背景.md)：① 先说无用 → ② 再说为什么做它 →
> ③ 落在「换一种记录方式，能得到什么」。**不是反效率，不是解决痛点。**

> 本篇与 [05 · 下一版方向定调](05-下一版方向定调.md) 同一口径。
> 核心交互是首页**那颗会随时间变密的球**，以及**攒元素 → 长按「记下此刻」**；
> 界面细节见 [15 · 首页界面方案](15-首页界面方案.md)。

## 亮点一：把「无用」写进类型系统

首页那些效率数字是**算不出来**，不是忘了渲染——`Entry` 类型上根本不存在能算出
「专注时长」「完成率」「连续天数」的字段。

```ts
// app/src/features/memory/types.ts
export interface Entry {
  id: string
  kind: EntryKind
  createdAt: number
  text?: string
  durationMs?: number
  blobRef?: string
  tags: EntryTags
  tagSource: TagSource
  meta?: EntryMeta
  momentId?: string
}
// 没有 streak、没有 completionRate、没有 dailyGoal、没有 done
// （meta 是采集侧的客观测量值，momentId 是同一次「此刻」的组号——都不是能算出「有用」的字段）
```

这条线在四个地方同时被钉住，任何一处想「顺手加回来」都会红：

| 位置 | 守卫 |
| --- | --- |
| `memory/types.ts` | 类型上没有可累加字段 |
| `memory/db.ts` | 表结构里没有 `focusSessions` / `stats` / `streaks` |
| `memory/repo.test.ts` | 断言 `Entry` 的键不含 9 个效率词 |
| `memory/extract.ts` | 标签词典刻意不含「完成 / 坚持 / 进步 / 加油」等评价性词 |

计数只活在**读的那一瞬间**，不落回条目上：

```ts
// app/src/features/memory/aggregate.ts
/** 全部是纯函数：`Entry` 上永远不多一个字段。计数只活在读的这一瞬间。 */
export function countByTheme(entries: readonly Entry[], theme: string): number {
  return entries.filter((entry) => entry.tags.themes.includes(theme)).length
}
```

**为什么重要**：类型系统里表达不出来的「有用」，界面上也就做不出来。
这一条比任何一句文案都管用——它把产品哲学从「靠自觉遵守」变成了「编译期强制」。

## 亮点二：首页是一颗会随时间变密的球

用户打开 App 第一眼看到的不是功能，而是**一颗用网点画出来的球**；
留得越多、网眼越密 —— **密度就是那个数字**，界面上一个数字都不写。

| 用户留下 | 球的变化 |
| --- | --- |
| 一段环境声 | 网眼密一点 |
| 一张照片 | 网眼密一点 |
| 一句话 | 网眼密一点 |
| 什么都没留下 | 它不动 —— 不留也是一次留，但留的不是数据 |

**界面上一个数字都不写**：密度就是那个数字，只是它不可被计算。
它不是柱状图，不是数字，不是统计。

**为什么废掉「不可用的 START FOCUS」**：上一版把「按不动的专注按钮」当核心交互，
概念上聪明，但在真实产品里出了一处硬伤——用户第一眼看到的顺序仍是
`时钟 → 专注 / 完成率 / 连续天数 → 今日任务 → START FOCUS`，视觉上依然在说
「这是一个专注 / 自律 App」，只是等用户点下去以后再告诉他「我其实不是」。

> 不是「没有视觉焦点」，是**视觉焦点放错了**。大时钟和 START FOCUS 抢走的是错误的注意力。

所以这一版把效率语言整块移出首页（专注 / 完成率 / 连续天数 / 今日任务 / START FOCUS），
连带 `refuseCount` / `refuse()` 一起成为死代码被删除。**行动入口交给「理解」——
只在真的出现时提供。**

首页的视觉纪律见 [15 · 首页界面方案](15-首页界面方案.md)：**一屏只有一个彩色主体**
（那颗球），**空与满只由网点密度表达，不做色相插值** ——
冷青与暖金一平均就是一团没有色相的土黄灰，那是上一版「脏」的来源。

## 亮点三：记录就是「无用」的存档方式

「此刻」提供文字 / 图片 / 声音三个**真实**入口（真麦克风、真相机），可以一次攒下
好几个再一起落下——它们从此是**一件事**（共享一个 `momentId`），不是三条记录。
而「什么也不留」**收在右上角一个安静的角**：它不跟这三个入口抢层级，
但「不留下也是完整的答案」这条没有变。

这不是「记录」与「无用」并列的两个功能。恰恰相反：

> **记录就是无用的存档方式**——按「文件类型」存的相册会留不下的（一段空调声、
> 一句「今天风很大」、一个说不清意义的树影），在这里被完整留下；
> 而时长、完成率、连续天数这类「事后要用到的量化信息」，这里一条都不采。

三种媒介各有其不可替代的意义：

- 📷 **照片**：留下「我看到了什么」。
- ✍️ **文字**：留下「我当时在想什么」。
- 🎙 **声音**：留下「这一刻真实是什么感觉」。

> 相册保存的是文件；我们想保存的是感受。

采完**不给奖励**——没有 ✦、没有「已保存」的成就感设计，浮层直接收起、东西只是攒到球边；
长按落下时也没有撒花，只有球悄悄变密一点。这是全片的转折：你做了唯一能做的事，
而它不产生结果。

## 亮点四：AI 是一面镜子，不是教练

AI 的角色是「时间观察者 / 时间考古学家」，三层能力：

1. **看见当下** — 理解用户当前留下的文本、声音、照片和语境。
2. **看见过去** — 从用户自己的记录中找到相关记忆，并在需要时重新呈现。
3. **看见关系** — 识别长期模式（开始重要任务前频繁停留、某类场景容易焦虑……）。

**输出原则**：先观察不评价，先提问不说教，先帮助理解自己再提供行动建议，
不制造新的绩效压力，不替用户决定什么是有用。

> AI 不给你一份报告，它只是把你留下过的时刻，重新讲给你听。

### 但它不长得像聊天机器人（2026-09-26 定调）

上一版最大的损失是：**AI 理念很特别，UI 却把它做成了聊天机器人**——一排排
「AI 说一句 → 用户选一句 → 输入框」，太普通了。新形态叫**「发现」**：

- 不是每天汇报；只有它真的发现某个关系时，才出现一张卡；
- 点开看到的**不是结论**（「最近你压力比较大」），而是**证据**：

> 9 月 3 日，23:47 —— 你留下了一段洗衣机的声音。
> 9 月 11 日，00:18 —— 你写：「终于没人找我了。」
> 昨天，23:52 —— 你什么也没写，只录了 31 秒窗外。

然后 AI 只说一句：**「这三次，你都在所有人安静以后才留下东西。」**
再问：**「这是一天里唯一真正属于你的时间吗？」**

这才有「被认出来」的感觉。展开顺序有一条铁律：**先材料，后结论**。

## 亮点五：3 分钟专注不留痕

从「我必须完成」变成「这是我真正想做的」——这一次按钮按得下去，因为那是你自己想做的。
但它**不计数、不进时间流、不形成连续天数**：

> 一旦「专注 → 记录 → 连续 → 有用」这条回血链接通，产品就退回一个普通的计时工具了。

对应到工程上：`focusSession` 不落库、不进任何表、结束即消失，所以数据库里
**连一张 focus 表都没有**（见亮点一的 `db.ts`）。

> **现状**：「理解」里那一次行动出口已经存在，但**倒计时本身没做** ——
> 它落到的是那个不计时的呼吸浮层。这不是遗漏，是刻意的：计时一旦存在，「完成」就会回来。

**同时补齐一个叙事漏洞**：如果整场戏的落点永远是「他终于愿意工作了」，
产品价值会被不知不觉拉回「一个劝你去工作的应用」。所以行动不再是终局，
它只是 [00 · 核心路径](00-项目背景.md#核心路径与终局) 里的出口之一。

## 亮点六：记忆检索不做向量 RAG

这是本产品里最反直觉、也最值得讲的技术抉择。文档里最精彩的两个场景，
恰好是向量检索的盲区：

| 场景 | 真实需要 | 为什么向量检索办不到 |
| --- | --- | --- |
| 「你还记得 8 月 17 日吗？」 | 按**精确日期**召回 | 语义搜「焦虑」永远命不中「今天风很大」 |
| 「你已经提到它 7 次了」 | 跨条目 **COUNT** 聚合 | 这是聚合查询，不是 top-k 相似 |

所以检索走三路：**结构检索 → 聚合 → 文本兜底**，候选全量喂给长上下文模型。

> 护城河在**写入时的标签提取**，不在检索算法。

落地形态：

```ts
// app/src/features/memory/aggregate.ts —— 路二：聚合
/** 精确日期检索：容差内离目标最近的那条。平手时优先「word 且有 text」——
 *  8/17 那张卡片要的是那句话，不是一条没有文字的声音。 */
export function entryNearestDate(entries, targetTs, toleranceMs): Entry | undefined
```

这一判断直接决定了数据模型：`Entry.tags` 在写入那一刻由 AI（或规则）提取一次
（一次不可回退的加工），而所有标签维度（themes / emotions / people / places）
**刻意不建索引**——个人几千条封顶，内存过滤是微秒级，为嵌套数组建 `multiEntry`
索引只会让写入路径变复杂。详见
[04 · 技术实现](04-技术实现.md#五本地优先的记忆层与索引策略)。

## 与「按文件类型存」的传统记录方式的差异

| 传统做法（相机 / 录音机 / 备忘录 / 相册） | 「此刻」的做法 |
| --- | --- |
| 一个文件一条记录，照片、录音、文字各归各的 | **一个场景一条记录**：一次攒下的东西共享 `momentId` |
| 默认你会拍很多张、凑一套素材 | **不必凑齐**；只有照片、只有一句话、只有声音都成立 |
| 按时间倒序排列，呈现的是文件 | 按**线索**串起来，回看时回到现场（风声真的响起来） |
| 事后要自己翻、自己想「当时为什么留下」 | 线索让散落的碎片自己浮出来（不同日期的树、那只白猫） |
| 想找某件事只能靠翻相册 | 说出大概就能找回：「把以前记下的那些第一次，也帮我找出来」 |
| 首页显示「今天留下 N 条」「已连续 N 天」 | 首页只有一颗正在变密的东西，**不给数字** |
| AI 给总结、给结论、给建议清单 | AI **只呈现，不解释**；结论由用户自己认出来 |
| 记录会变成图表和数据 | 记录只让球变密一点，不进入任何统计 |

## 隐私亮点

- **原音原图默认不出设备**：只有**文本与标签**会离开设备，原始音频/图片全部存应用私有目录（IndexedDB 的 `blobs` 表）。**唯一的例外**是「让 AI 看一眼画面」这个开关（默认关、需显式打开）：打开后照片缩到 512px、剥掉 EXIF/GPS 再发出去，详见 [24 · 打标与检索](24-打标与检索.md) §四。
- **API Key 永不出服务端**：LLM 调用经开发期代理转发，Key 只存在 `.env.local`，绝不进客户端产物（详见 [03 · 技术架构](03-技术架构.md#七隐私边界)）。
- **能本地完成的分析优先本地完成**：写入时的标签提取默认走本地规则词典 + 元数据，不联网；视觉 LLM 只是可选的增强层，关着时一切留在本机。
- AI 不给用户贴心理疾病、人格等标签；观察一律表达为「我注意到……」而非「你就是……」。
- 用户可以随时删除单条记录或全部时间档案（`clearEntries`）。
