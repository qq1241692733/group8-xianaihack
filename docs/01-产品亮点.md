# 01 · 产品亮点

核心判断先摆在这里：

> **无用不是「不能」，是「不算」。**

这不是一句文案，而是贯穿数据层、交互层、文案层的一条设计约束。下面六个亮点，
前三个在 `app/` 里已经由类型系统与代码结构**强制**实现。

---

## 亮点一：把「无用」写进类型系统

首页假装是个效率仪表盘，四个数字里有两个永远是 `—`。**这不是忘了渲染，是算不出来**——
`Entry` 类型上根本不存在能算出「专注时长」「完成率」「连续天数」的字段。

```ts
// app/src/features/memory/types.ts
export interface Entry {
  id: string
  kind: EntryKind
  createdAt: number
  text?: string
  durationMs?: number
  blobRef?: string
  tags: EntryTags
  tagSource: TagSource
}
// 没有 streak、没有 completionRate、没有 dailyGoal、没有 done
```

数据库层同样把这条线写死——连表都没有：

```ts
// app/src/features/memory/db.ts
this.version(1).stores({
  entries: 'id, createdAt, kind, [kind+createdAt]',
  blobs: 'id',
  meta: 'key',
})
// 表结构里没有 focusSessions、没有 stats、没有 streaks。
// 3 分钟专注不落库，所以它连一张表都没资格拥有。
```

并且有测试守住这条线，防止后人「顺手」加回来：

```ts
// app/src/features/memory/repo.test.ts
const forbidden = ['streak','completionRate','dailyGoal','done','completed','status','score','progress','count']
expect(Object.keys(entry).filter((key) => forbidden.includes(key))).toEqual([])
```

**为什么重要**：类型系统里表达不出来的「有用」，界面上也就做不出来。
这一条比任何一句文案都管用——它把产品哲学从「靠自觉遵守」变成了「编译期强制」。

## 亮点二：不可用的 START FOCUS

首屏最显眼的按钮，按下去**不启动**。它躲开你，并依次说：

> 为什么这么着急？ → 它不会启动。今天不会。 → 好。那就先不做。

与此同时，唯一真正管用的入口（**留下一刻**）被故意做成一整行里最小的字。

```tsx
// app/src/screens/MomentScreen.tsx
const REFUSE_LINES = ['为什么这么着急？', '它不会启动。今天不会。', '好。那就先不做。']

function handleFocusClick() {
  const x = (Math.random() * 7 - 3.5).toFixed(1)   // 它躲开你
  const y = (Math.random() * 7 - 3.5).toFixed(1)
  setJitter(`translate(${x}px, ${y}px)`)
  setMsg(REFUSE_LINES[Math.min(refuseCount, REFUSE_LINES.length - 1)] ?? '')
  refuse()
}
```

**交互原则**：按钮不是所有时候都可用；系统状态随用户心理状态改变；
**不可用本身就是表达，可用本身就是产品叙事**。

## 亮点三：记录就是「无用」的存档方式

「留下此刻」提供声音 / 照片 / 一句话三个**真实**入口（真麦克风、真相机），
而「什么都不留下」与它们**同等显眼**——那也是一个完整的答案。

这不是「记录」与「无用」并列的两个功能。恰恰相反：

> **记录就是无用的存档方式**——它保留效率 App 会删掉的（一段空调声、一句「今天风很大」），
> 删掉效率 App 会保留的（时长、完成率、连续天数）。

三种媒介各有其不可替代的意义：

- 📷 **照片**：留下「我看到了什么」。
- ✍️ **文字**：留下「我当时在想什么」。
- 🎙 **声音**：留下「这一刻真实是什么感觉」。

> 相册保存的是文件；我们想保存的是感受。

留下之后**不给奖励**——没有 ✦、没有「已保存」的成就感设计，只回原处，
只在首页多一条**虚线**。这是全片的转折：你做了唯一能做的事，而它不产生结果。

---

## 亮点四：AI 是一面镜子，不是教练

AI 的角色是「时间观察者 / 时间考古学家」，三层能力：

1. **看见当下** — 理解用户当前留下的文本、声音、照片和语境。
2. **看见过去** — 从用户自己的记录中找到相关记忆，并在需要时重新呈现。
3. **看见关系** — 识别长期模式（开始重要任务前频繁停留、某类场景容易焦虑……）。

**输出原则**：先观察不评价，先提问不说教，先帮助理解自己再提供行动建议，
不制造新的绩效压力，不替用户决定什么是有用。

> AI 不给你一份报告，它只是把你留下过的时刻，重新讲给你听。

---

## 亮点五：3 分钟专注不留痕

从「我必须完成」变成「这是我真正想做的」——这一次按钮按得下去，因为那是你自己想做的。

但它**不计数、不进时间流、不形成连续天数**：

> 一旦「专注 → 记录 → 连续 → 有用」这条回血链接通，产品就退回普通番茄钟了。

对应到工程上：`focusSession` 不落库、不进任何表、结束即消失，所以数据库里
**连一张 focus 表都没有**（见亮点一的 `db.ts`）。

---

## 亮点六：记忆检索不做向量 RAG

这是本产品里最反直觉、也最值得讲的技术抉择。文档里最精彩的两个场景，
恰好是向量检索的盲区：

| 场景 | 真实需要 | 为什么向量检索办不到 |
| --- | --- | --- |
| 「你还记得 8 月 17 日吗？」 | 按**精确日期**召回 | 语义搜「焦虑」永远命不中「今天风很大」 |
| 「你已经提到它 7 次了」 | 跨条目 **COUNT** 聚合 | 这是聚合查询，不是 top-k 相似 |

所以检索走三路：**结构检索 → 聚合 → 文本兜底**，候选全量喂给长上下文模型。

> 护城河在**写入时的标签提取**，不在检索算法。

这一判断直接决定了数据模型：`Entry.tags` 在写入那一刻由 AI 提取一次（一次不可回退的
加工），而所有标签维度（themes / emotions / people / places）**刻意不建索引**——
个人几千条封顶，内存过滤是微秒级，为嵌套数组建 `multiEntry` 索引只会让写入路径变复杂。
详见 [04 · 技术实现](04-技术实现.md#二本地优先的记忆层与索引策略)。

## 与传统时间管理 App 的关键差异

| 传统做法 | 「此刻」的做法 |
| --- | --- |
| 首页展示「今天浪费了 2h47m」 | 「今天，你拥有 2 小时 47 分钟」——不评价 |
| 主按钮「开始专注」按下去就计时 | 同一个按钮，按下去**不启动**。它在拒绝你 |
| 要求用户主动记录浪费时间 | 用户只需留下此刻，无用由 AI 自己发现 |
| AI 输出效率报告 | AI 重构你的时间叙事，帮你重新看见自己 |
| 专注 = 完成任务的 KPI | 专注 = 内在状态自然发生后的行动 |
| 记录会变成图表和数据 | 记录只留下一条痕，不进入任何统计 |

## 隐私亮点

- **原音原图永不出设备**：只有**文本与标签**会离开设备，原始音频/图片全部存应用私有目录（IndexedDB 的 `blobs` 表）。
- **API Key 永不出服务端**：LLM 调用经开发期代理转发，Key 只存在 `.env.local`，绝不进客户端产物（详见 [03 · 技术架构](03-技术架构.md#隐私边界)）。
- **能本地完成的分析优先本地完成**。
- AI 不给用户贴心理疾病、人格等标签；观察一律表达为「我注意到……」而非「你就是……」。
- 用户可以随时删除单条记录或全部时间档案（`clearEntries`）。
